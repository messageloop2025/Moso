# 数据库更新模块

**原则：代码不兼容老版本数据库结构。** 系统启动时通过本模块检查当前数据库版本，并**按顺序执行升级脚本**，将数据库升级到代码所要求的版本，从而保证运行期使用的始终是当前代码所兼容的结构。

## 项目规则（必须遵守）

- **任何修改数据库结构的操作**（增/删/改表、列、索引等）**都将引起数据库版本增加**，并**必须**在本目录下**新增对应的数据库升级脚本**。
- 不得在业务代码中为“兼容老库”写分支逻辑；老库通过启动时执行升级脚本变为新结构。

## 版本号规则

- 每次修改数据库结构，**目标版本号 +1**。当前版本号保存在表 `schema_version`（单行，`version` 字段）。
- 版本 0 表示「未初始化」或空库。
- **原始数据库**：引入本版本机制之前已存在的库（无 `schema_version` 或版本为 0，但已有 `users` 等业务表），统一识别为**版本 1**，不执行 000，仅从 001 起按需升级。

## 升级脚本约定

- **命名**：`NNN_描述.py`，如 `000_initial.py`、`001_add_xxx.py`。`NNN` 为三位数字。
- **含义**：编号 N 表示「从版本 N 升级到版本 N+1」的脚本，**只做这一档升级**。
- **接口**：脚本内必须定义 `async def upgrade(db)`，接收当前数据库连接，执行本档 DDL/数据变更。
- 若数据库版本较老，会按 000、001、002… 顺序依次执行，直到达到最新版本。

## 新增一次结构变更的步骤（必做）

1. **确定下一版本号**：当前最新版本为 N 时，下一版本为 N+1。
2. **在本目录新增升级脚本** `NNN_描述.py`，其中 NNN = 当前最新版本（三位数，如 001、002）。
3. 在脚本中实现 `async def upgrade(db):`，**仅做**从版本 N 到 N+1 的 DDL/数据变更（单次 ALTER、单张新表等）。
4. 提交后，下次系统启动时会自动执行该脚本，将数据库升级到新版本。**未添加脚本的库结构修改不得合并。**

## 示例：001 增加某列

```python
# 001_add_foo_column.py
async def upgrade(db):
    await db.execute("ALTER TABLE some_table ADD COLUMN foo TEXT DEFAULT ''")
    await db.commit()
```

## 注意事项

- 每个脚本只负责「当前版本 -> 下一版本」，不要在一个脚本里写多档变更。
- 脚本执行顺序严格按编号；不要修改已有脚本内容，否则已升级过的库会不一致。
- 可写幂等逻辑（如 `IF NOT EXISTS`、`has_column` 再 ADD COLUMN）以兼容异常重跑。
