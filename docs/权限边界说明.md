# 毛竹 权限边界说明

本文档汇总所有与权限、数据隔离相关的边界，便于审计与对接。

---

## 1. 角色与判定

- **角色**：`admin`、`manager`、`管理员` 视为管理员；其余为普通用户。
- **API 层**：`api/auth.py` 中 `_is_admin_role(role)` 与 `require_admin`（依赖 `get_current_user`）。
- **Skills 层**：`services/ai_skills.py` 中 `_is_admin(user)`，与 API 判定一致（admin/manager/管理员）。
- **用户管理**：修改/删除用户时，**仅当目标为管理员角色时** 需当前用户也是管理员（`_is_admin_role`），避免普通管理员误改超级管理员。

## 2. 按模块的权限边界

### 2.1 认证（api/auth.py）

| 接口 | 认证 | 说明 |
|------|------|------|
| GET /auth/captcha | 否 | 公开 |
| POST /auth/login、register | 否 | 需验证码；登录连续 5 次密码错误将锁定账户 |
| GET /auth/me | 是 | 当前用户信息 |
| POST /auth/change-password | 是 | **仅改当前用户自己的密码**（old_password + new_password） |
| POST /auth/forgot-password、reset-password、request-unlock、unlock-by-token | 否 | 忘记密码/邮件重置/请求解锁/邮件解锁（需配置 SMTP、site_url 与用户邮箱） |

---

### 2.2 用户管理（api/users.py）

| 接口 | 权限 | 说明 |
|------|------|------|
| GET/POST /users、PUT/DELETE /users/{id}、POST /users/{id}/reset-password、POST /users/{id}/unlock | **仅管理员** | 列表（含 email、locked_until）/创建/更新（含 email）/**删除（级联清理该用户一切数据，含其主机在被分享用户侧形成的聊天记录等）**/重置密码/解锁 |
| POST /users/me/delete | **任一已登录非管理员用户（自助注销）** | 体 `{password, confirm:"DELETE"}`；校验当前密码并经二次确认后，执行与管理员删除完全相同的级联清理；管理员账户被拒绝以避免误删最后一位管理员 |
| 更新用户 | 管理员可改普通用户及 **email**；**仅管理员可改管理员账户**（含 admin/manager/管理员） |
| 删除用户 | **不可删除管理员角色账户** |

### 2.3 主机（api/hosts.py）

| 接口 | 权限 | 说明 |
|------|------|------|
| GET /hosts、/hosts/stats、/hosts/{id} | 登录 | 所有登录用户共享同一主机列表，无按用户过滤 |
| POST/PUT/DELETE /hosts、POST /hosts/{id}/execute、/check-type | 登录 | 任意登录用户可增删改主机、执行命令、检测类型 |

**设计说明**：主机与凭证为全局资源，未做「仅管理员可增删主机」限制；若需仅管理员可维护主机，需在 create_host/update_host/delete_host 上改为 `require_admin`。

### 2.4 主机分组（api/host_groups.py）

|------|------|------|
| GET /host-groups、/tree、/{id}、/{id}/hosts | 登录 | 普通用户仅见自己创建的分组；管理员可见全部 |
| POST/PUT/DELETE /host-groups、POST/DELETE /host-groups/{id}/hosts | **分组创建者或管理员** | 任意登录用户可创建自己的分组；可将**自己有访问权的主机**（自有 + 他人分享）加入**自己创建的分组**；不可操作他人创建的分组（管理员除外） |

### 2.5a 服务凭证（api/service_credentials.py）

需全局 **`credentials_vault_enabled=true`**。凭证按 **用户 + service/address/port/username** 匹配，**不绑定操作主机**。

| 接口 | 权限 | 说明 |
|------|------|------|
| GET /service-credentials/enabled | 登录 | 功能是否开启 |
| GET /service-credentials | 登录 | 仅当前用户自己的凭证 **元数据**（无 password） |
| POST/PUT/DELETE /service-credentials | 登录 | 增删改；密码写入后不可读出 |

AI 工具 `send_service_password` 注入时写 `operation_logs`（`credential_vault:inject`），不含明文。

| 接口 | 权限 | 说明 |
|------|------|------|

## 3. Skills（AI 工具）权限与数据边界

- **get_ai_config / update_ai_config**：当前用户读写**激活 Profile**（经 `user_ai_config.active_profile_id`）；**管理员可传 user_id 读写任意用户**的 AI 配置。与 Web `/model-config` 及 `POST /ai/config` 一致。
- **/ai/profiles***：当前用户 CRUD、激活、导入导出自己的 Profile；**管理员可传 user_id 代管**。
- **apply_system_ai_config_to_user**：仅管理员，将系统默认 AI 配置（settings 表）写入指定用户的**当前激活 Profile**（无则创建默认）。
- **list_logs**：普通用户仅能查自己的日志（强制 `user_id = 当前用户`）；管理员可传 `user_id` 筛选。
- **fs_***（fs_list、fs_search、fs_read_file、fs_write_file、fs_read_binary、fs_write_binary、fs_truncate、get_chats_workspace_dir、fs_mkdir、fs_pack_tgz、fs_unpack_tgz、fs_delete、fs_copy）**：作用范围为 **web/fs/当前用户名**，无 username 参数，AI 无法代管理员访问他人目录。
- **memory_***：仅当前用户 `web/fs/<本人>/memory/`；禁止写入密码/密钥。
- **markdown_***：按 `file_root` 限定在本人 fs / 帮助文档 / 本人 Skill 目录内。
- **search_web / search_github / list|configure_search_provider**：使用**当前用户**的搜索服务配置；密钥不回显。
- **local_chat_***：仅管理员本机管理会话；推荐落盘在本人工作区约定路径下。
- **create_host / update_host / delete_host、凭证/分组/批量/系统设置/用户管理**：与 API 一致，需管理员处均做 `_is_admin(user)` 校验。
- **change_my_password**：仅改当前用户密码；**reset_user_password**：仅管理员；**reset_user_system_ai_usage**：仅管理员（清零某用户系统共享 Key 调用计数）。
- **系统共享 Key 配额**：未配置自有 API Key 的用户自动使用系统共享 Key，每用户有调用次数上限（**默认 2000**）；**配置自有 KEY 后解除次数限制，不再计入本机制**。使用共享 Key 时 `/api/ai/chat` 在 SSE 首部下发 `trial_info`，并在首条 assistant 回复前追加配额横幅；**「模型配置」页**同步展示。达上限后：`/api/ai/chat` 不 403，而以固定文案流式回复（`trial_info.exhausted=true`）；一次性 summarize 类端点仍 **403**。
- **管理员重置配额 / 写入系统配置**：入口等价：
  - UI：「用户管理 → 用户行 → AI 配额」→「重置共享 Key 计数」或「写入系统配置并解除次数限制」；
  - HTTP：`POST /ai/config/trial/reset?user_id=<id>` / `POST /ai/config/trial/unlock?user_id=<id>`；
  - AI：`reset_user_system_ai_usage` / `apply_system_ai_config_to_user`。
- **维护历史**：create 写入当前用户为 created_by；**update_maintenance / delete_maintenance** 仅**创建人或管理员**可执行（API 与 Skills 均已加校验）。
- **get_user_mail_settings / update_user_mail_settings / send_email**：仅当前用户个人 **user_mail_config**；**send_bind_email_code**（绑定邮箱验证码）仍走**系统** SMTP，不要求个人发信已启用。
- **read_chat_attachment / list_chat_attachments / save_image_description**：仅当前用户的 `chat_attachments` 行及对应磁盘文件；Office/PDF 转换在服务端 MarkItDown 完成，不扩大跨用户访问面。
- **create_chat_artifact / update_chat_artifact / list_chat_artifacts / read_chat_artifact_file**：成果物目录与元数据均按 **user_id** 隔离。
- **list/write/delete_user_skill_file / run_skill_script**：仅本人 `skills/<name>/`；禁止改写他人 Skill；`run_skill_script` 仅执行该 Skill `scripts/` 内脚本。
- **list_user_mcp_servers / configure_user_mcp_* 等**：仅当前用户的 `user_mcp_servers`；stdio MCP 在服务端进程所在机器启动。
- **list_user_skills / save_user_skill 等**：仅当 `users.skills_enabled=1` 时可用；Skill 文件仅落在 `web/fs/<当前用户名>/skills/`。

## 4. 数据隔离汇总

| 资源 | 普通用户 | 管理员 |
|------|----------|--------|
| 操作日志 | 仅看自己 | 全部 + 可选 user_id 筛选 |
| 本地文件系统 | 仅 web/fs/自己 | 自己 + 可选 username= 指定用户 |
| AI 配置 | 仅自己的 Profile 与激活项；管理员可读写任意用户的 + 将系统配置应用到用户 | 同左 |
| AI 会话/消息 | 仅自己的 | 同左 |
| 个人发信（user_mail_config） | 仅自己的 | 同左（无「管理员代配他人 SMTP」接口） |
| 终端 buffer/send | 仅自己的 (user_id, slot) | 同左 |
| 主机/分组/凭证/批量/用户/全局设置 | 见上表（读/写权限分离） | 可管理 |
| 维护历史 | 可看全部；仅可改删自己创建的 | 可改删全部 |
| 最佳实践 | 可看可改全部（无创建人限制） | 同左 |

## 5. 已修复的边界问题（本次检查）

1. **get_ai_config / update_ai_config（Skills）**：原为读写在全局 settings 且 update 需管理员；已改为读写 **当前用户** user_ai_config，与 Web API 一致，无需管理员。
2. **用户管理**：更新/删除用户时，原仅判断 `role == "admin"`；已改为 `_is_admin_role(target.role)`，避免误改「管理员」/「manager」等角色。
3. **维护历史**：PUT/DELETE 原未校验创建人；已改为**仅创建人或管理员**可修改/删除（API + Skills 均已加校验）。
