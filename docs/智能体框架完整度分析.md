# Moso 智能体框架完整度分析

> 审计时间：2026-07-29  
> 方法：对标通用智能体框架 20 个核心维度，逐项核查代码实现  
> 统计：✅ 已完善 8 项 | ⚠️ 部分具备 7 项 | ❌ 完全缺失 4 项 | 不计 1 项

---

## ✅ 已完善（8 项）

### 3. Planning / 任务规划

5 个委派/工作流工具，覆盖串行编排、并行委派、模板复用：

| 工具 | 说明 |
|------|------|
| `delegate_to_cli_agent` | 任务委派给远端 CLI 子 AI |
| `delegate_chain` | 多步编排链（delegate/ssh/sleep 步骤） |
| `delegate_to_edgeops_ai` | 内部子 AI 委派（递归深度=2） |
| `delegate_sub_tasks_batch` | 批量并发子 AI（1-8 个，Map-Reduce） |
| `run_workflow_template` | 执行可复用工作流模板 |

### 4. Multi-modal / 多模态

- Vision 图像理解 + 图像附件编辑 + region 裁剪
- Vision 降级 fallback（3 级压缩 stage）
- 局限：无 Audio/Video 输入

### 5. Model Router / 模型路由

- Model Profile 系统：多 Profile 切换（Aliyun/Ollama/OpenAI）
- 每个 Profile 含 api_key / base_url / model / system_prompt / provider
- 局限：无自动 fallback，无按任务智能路由

### 6. Prompt Management / 提示词管理

- 多级 system prompt 构建函数（`_build_system_prompt` / `_build_assistant_system_prompt`）
- 按 scope 裁剪（`_sanitize_system_prompt_local_scope`）
- 按角色裁剪（`_sanitize_system_prompt_for_role`）
- MCP 上下文提示 / Event 事件引擎提示独立注入
- 用户可通过 Model Profile 覆盖 system_prompt
- 局限：无版本化，无 A/B 对比

### 9. Context Window / 上下文管理

- 比例预算分配（Hosts 15% / Groups 10% / Knowledge 15% / Terminal 30% / History 30%）
- 自动模型检测推算 context budget（如 qwen3.6 ≈ 262K chars）
- 截断（`_truncate_segment`）+ 压缩（`_compress_messages_image_urls`）+ 摘要（`summarize_old_assistant`）
- 工具结果缓存截断（`_clip_tool_result_cache_content`）
- 局限：仅按字符估算，无精确 token 计数

### 15. Error Recovery / 错误恢复

- LLM 超时重试 + 可配重试次数（`AI_CHAT_LLM_TIMEOUT_RETRIES`）
- Vision 降级回退（3 级压缩）
- SSH 连接 `legacy-rsa` 自动回退
- MCP session circuit breaker 模式
- 3 种自动 nudge 重试（spill_read / image_blind / short_final）
- 局限：无成熟的指数退避库

### 16. Multi-Agent / 多智能体协作

- 5 个委托工具覆盖串行/并行/Map-Reduce 编排
- 批量并发支持 1-8 个子 AI
- 工作流模板复用
- 局限：递归深度硬限制=2，无 swarm/crew 等框架级协作

### 18. Streaming / 流式控制

- 完整 runtime control：stop / pause / resume / supplement / choice / wake / hook_choice
- LLM 生成期间可抢占式中断
- 流式输出中实时检测控制指令
- 工具执行期间响应暂停/停止

## ⚠️ 部分具备（7 项）

### 1. Memory / 记忆

**已有**：5 个 Memory 工具（search/write/read/list/rebuild_index），文件系统存储（Markdown + INDEX.md），按 hosts/topics/journal 组织

**缺失**：
- 无向量化存储（无 Embedding）
- 无语义检索（仅纯文本/正则匹配）
- 无跨会话长期记忆召回

### 8. Feedback Loop / 反馈闭环

**已有**：6 个反馈工具 + 完整前端反馈页面，支持提交/编辑/撤回/管理员回复/忽略/标记已读

**缺失**：
- AI 不会自动从反馈中学习改进
- 无 `regenerate` / `thumbs_up` / `dislike` 即时反馈按钮

### 10. Cache / 缓存

**已有**：Session 级工具允许缓存 + markitdown 转换旁路 + MCP skip bucket

**缺失**：
- 无 Redis 集成
- 无 LLM 响应缓存
- 无语义缓存（相同语义查询复用结果）

### 11. Cost Tracking / 成本追踪

**已有**：系统 API key 使用次数上限（`SYSTEM_AI_USAGE_LIMIT = 2000`）

**缺失**：
- 无 Token 用量按用户/会话/模型维度统计
- 无金额成本估算
- 无预算告警

### 12. I/O Guard / 安全护栏

**已有**：路径逃逸防护 + 终端发送内容防护 + SSRF 阻止内网 IP + HTTPS 强制

**缺失**：
- 无 jailbreak 检测
- 无 PII / 敏感信息过滤
- 无内容审核集成

### 13. Scheduled Tasks / 定时任务

**已有**：16 个定时/触发任务工具，支持 cron + 触发式

**缺失**：
- cron 精度仅到分钟（无秒级）

### 19. Plugin / Skill Market / 插件市场

**已有**：完整 Skill 导入/导出（JSON + TGZ）

**缺失**：
- 无 Skill 市场/商店
- 无公开浏览/发现
- 无发布/分享到公共仓库
- 无星级/评论/评分

### 20. Granular Permissions / 细粒度权限

**已有**：admin/user 二值角色，约 50+ 处 `_is_admin_role` 调用

**缺失**：
- 无 RBAC 多角色体系
- 无 permission 表
- 无资源级 ACL
- 无 API key 作用域限制

## ❌ 完全缺失（4 项）

### 2. RAG / 知识库

**完全缺失**：
- 无向量数据库（Chroma/Pinecone/Milvus/FAISS 均未集成）
- 无文档 Embedding / Chunking pipeline
- 无通用语义检索工具
- 运维场景影响：AI 无法"看懂"几百份运维文档，只能靠 prompt 注入和 Memory 文本搜索

### 7. Evaluation / 评测

**完全缺失**：
- 无 LLM eval harness
- 无 benchmark 数据集
- 无 accuracy / precision / recall 度量
- 无回归测试——改 prompt 或换模型后无法验证能力不退化

### 14. A/B Testing / A/B 测试

**完全缺失**：
- 无实验框架
- 无流量分流/桶分配
- 无模型 variant 对比

### 17. Conversation Branching / 对话分支

**完全缺失**：
- 无从某条消息重新生成（regenerate from message）
- 无 checkpoint / 版本回退
- 无对话分叉/合并

## 📊 补齐优先级建议

按**运维智能体场景**的重要性排序：

| 优先级 | 差距 | 场景价值 | 复杂度 |
|:--:|------|------|:--:|
| **P0** | RAG 知识库 | 让 AI 读懂几百份运维文档、故障手册 | 高 |
| **P0** | Memory 向量化 | 跨会话记忆：记住每台主机的历史操作和问题 | 中 |
| **P1** | 安全护栏（PII / 敏感信息） | 防止密码/token/内网 IP 泄露到 LLM | 中 |
| **P1** | Cost Tracking（Token 花费） | 多用户运营：按用户/会话/模型统计花费 | 低 |
| **P1** | Evaluation（回归评测） | 改 prompt / 换模型后验证不退化 | 中 |
| **P2** | RBAC 细粒度权限 | 多租户场景：限制特定用户只能用特定工具 | 中 |
| **P2** | LLM 响应缓存 | 高频相同查询减少重复调用 | 低 |
| **P3** | 对话分支 | 用户体验：尝试不同提问方向 | 中 |
| **P3** | Skill 市场 | 生态建设：用户间分享 Skills | 高 |

---

## 总结

Moso 在 **Agent 核心运行时**方面已经非常扎实：

- ✅ 完整的 Hook 事件引擎（EventBus + 3 层规则来源 + eval 条件判断）
- ✅ Middleware 中间件管线
- ✅ Agent 状态机 + 运行时控制
- ✅ 多智能体编排（委托/批量/Map-Reduce）
- ✅ 流式控制（stop/pause/resume 全覆盖）
- ✅ 上下文窗口智能管理

主要缺口集中在 AI 能力的 **"上游"**（知识检索 RAG + 记忆语义化）和 **"下游"**（评测 + 成本 + 安全护栏）。补齐这两端后，就是一个工业级的完整运维智能体平台。
