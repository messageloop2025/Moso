# 毛竹 开发与完善建议

本文档汇总**可能的周边与项目整体完善**方向，供后续迭代或团队协作时参考。与《功能清单》《软件设计文档》互补：功能清单描述「做什么」，本文档侧重「如何做得更稳、更易维护、更易扩展」。

**文档维护**：发版或较大功能合并后，建议同步核对 [README.md](../README.md)、[API文档.md](API文档.md)、[数据库结构.md](数据库结构.md)（含 `schema_version` 与迁移编号）、[功能清单.md](功能清单.md)。当前代码目标库版本：**schema v31**（迁移脚本 **000–030**，含 **030** 移除离线版本申请相关表）。

## 1. 测试

| 方向 | 说明 | 现状（截至 v1.3.6） |
|------|------|---------------------|
| 单元测试 | 对纯函数与无 I/O 模块编写 pytest，避免重构漂移 | 已有 `tests/test_user_mcp_registry.py`、`tests/test_user_skills.py`、`tests/test_mcp_result_fetch.py`；可继续覆盖 `chat_utils`、`llm_adapter` 解析、locale 工具 |
| API 集成测试 | 登录、会话 CRUD、MCP/Skills API、反馈与留言板等 | **待补充**；建议 pytest + httpx + 独立 `EDGEOPS_DB` |
| 前端关键路径 | 登录、i18n 切换、AI 流式、会话提示词、MCP/Skills 页 | 以手工用例表或 Playwright 为辅；发版前跑 `python scripts/check_locale_parity.py` |
| 测试环境 | 独立 SQLite、独立端口，不污染开发库 | 可用内存库或 `EDGEOPS_DB=./test_edgeops.db` |

```bash
# 中英文文案键对齐（合并前建议执行）
python scripts/check_locale_parity.py

# 仅升级测试库结构
EDGEOPS_DB=./test_edgeops.db python scripts/migrate_db.py
```

## 2. CI / 流水线

| 方向 | 说明 |
|------|------|
| 静态检查 | 接入 ruff / mypy（可选）；前端为原生 JS，可选 ESLint 或仅 PR 人工审查 |
| 自动测试 | CI 中运行 `pytest tests/` + `check_locale_parity.py`；失败阻断合并 |
| 构建与镜像 | 将 `docker/` 构建纳入 CI；tag 与 `config.VERSION` / git tag 对齐 |
| 版本与变更 | 维护 `CHANGELOG.md` 或在 README 记录发版要点；数据库变更必须带迁移号（见 `database/migrations/README.md`） |

## 3. 代码规范与结构

| 方向 | 说明 |
|------|------|
| 分层与依赖 | 保持「api → services / database」单向依赖；共享逻辑放 `services/`，避免 api 与 services 循环引用 |
| 配置集中 | 敏感项与上限在 `config.py` + 环境变量（AI 步数、上下文、附件/MarkItDown、MCP、User Skills 体积等） |
| 错误与日志 | `/api/*` 未捕获异常统一 JSON（见 `app.py`）；关键路径打日志，可选带 `session_id` / `user_id` |
| 类型与文档 | 新增 Python 接口补充类型注解；复杂流程指向设计文档或 `web/aihelp/` |
| 下线功能 | 已移除的业务（如离线版本申请）应删路由/页面/文档引用；历史迁移 **016** 保留，**030** 负责删表，勿在业务代码为老库写分支 |

## 4. 日志、监控与可观测性

| 方向 | 说明 |
|------|------|
| 结构化日志 | AI 调用、工具执行、任务运行等可逐步改为 JSON 行，便于 ELK/Loki |
| 指标 | 可选 Prometheus（请求延迟、AI 次数、SQLite busy、定时任务执行） |
| 链路排查 | 为请求生成 `trace_id` 写入日志与错误响应 |
| 健康检查 | 当前有 **`GET /api/version`**（无认证）；**尚无** `/health` / `/ready`（DB ping、调度器状态）——容器/K8s 探针可暂用 version，或按 §2 实现专用探针 |

---

## 5. 安全加固

| 方向 | 说明 |
|------|------|
| 凭证与密钥 | 避免明文落库；生产必改 `EDGEOPS_SECRET`；JWT 与 SMTP 密钥轮换策略 |
| 输入校验 | 路径、host_id、session_id、artifact 路径等白名单；防目录穿越 |
| 限流与防护 | 登录验证码、留言板/反馈 IP 限频（已实现）；可对 AI 聊天按用户限流 |
| 依赖漏洞 | 定期 `pip audit` / Dependabot |
| 个人 MCP | stdio 命令在**服务端**执行，仅管理员/运维应能配置不可信命令；文档见 [外部集成与ClawOps.md](外部集成与ClawOps.md) |

---

## 6. 性能与容量

| 方向 | 说明 |
|------|------|
| 上下文与消息体 | `EDGEOPS_AI_CONTEXT_SIZE`、工具结果截断、`chat_tool_spill` 溢出到 `chats/.../spill/` |
| DB 与连接 | SQLite **WAL + busy_timeout**（见 [并发与扩展.md](并发与扩展.md)）；全局单 `aiosqlite` 连接，写仍串行 |
| 静态与缓存 | `/static` 可为 JS/CSS 加长期 `Cache-Control`（发版靠 `?v=` 查询参数，见 `index.html`） |
| 异步与超时 | 阻塞 SSH/MarkItDown/部分 MCP 走 `asyncio.to_thread`；LLM 用 httpx 异步 |
| 大文件 | 聊天附件、成果物 bundle 注意磁盘配额（`EDGEOPS_CHAT_ATTACHMENT_*`） |
