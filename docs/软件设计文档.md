## 1. 系统概述

毛竹 是以 SSH 为操作方式的远程 AI 运维系统。用户通过 Web 管理服务器树与凭证，在 AI 界面中通过自然语言与左侧 SSH 终端协同完成运维任务；AI 可调用 Skills 执行命令与文件传输，并可选需用户审批；所有操作与服务器维护历史均记录在案。

## 2. 架构概览

```
┌──────────────────────────────────────────────────────────────────────────┐

                                      │ REST / WebSocket / SSE
                                      ▼
┌──────────────────────────────────────────────────────────────────────────┐
│  FastAPI（app.py）                                                        │
│  auth/users/credentials/hosts/host_groups/host_tags                      │
│  ai_agent/chat_attachments/ai_artifacts | batch | terminal/ssh_channel   │
│  scheduled_tasks/triggered_tasks | user_mcp_servers/user_skills          │
│  login_board/feedback | integration_* | settings/dashboard/api_tokens …  │
│  内置 MCP 挂载 /mcp（services/edgeops_mcp）                               │
├──────────────────────────────────────────────────────────────────────────┤
│  EventBus 事件总线 ─ MiddlewareChain 中间件管线 ─ AgentStateMachine 状态机 │
└──────────────────────────────────────────────────────────────────────────┘
                    ┌─────────────────┼─────────────────┐
                    ▼                 ▼                 ▼
```

- **前端**：单页应用 + `web/locales` 中英文；AI 页终端（WebSocket）+ **SSH通道管理**（只读 xterm + channel WS）+ 多 Tab 聊天（SSE、流式 Markdown）。
- **后端**：FastAPI + 全局 `aiosqlite` 连接；阻塞 I/O 经 `asyncio.to_thread`；定时调度单进程推荐（见 [并发与扩展.md](并发与扩展.md)）。
- **外部集成**：OpenClaw、Hermes、REST/`eop_` Token、集成会话；每用户 MCP 与 Agent Skills。见 [外部集成与ClawOps.md](外部集成与ClawOps.md)。
- **安全**：凭证与主机分离；JWT；AI 工具调用可审批；按用户隔离数据与 `web/fs`。

## 3. 数据模型

完整表结构、列与索引见 **[数据库结构](数据库结构.md)**。本节为概要。

### 3.1 用户与权限

- **users**：id, username, display_name, password_hash, role, status, created_at, updated_at, last_login  
- 角色：admin / user；管理员可管理用户、凭证、分组、设置与审批策略。

### 3.2 凭证（与主机分离）

- **credentials**（统一凭证表，用 type 区分）  
  - id, type('password'|'key_pair'), code, name, description  
  - 密码型：username, password_enc  
  - 密钥型：username, key_type('RSA'|'ECC'), key_bits, public_key, private_key_enc  
  - created_at, updated_at, created_by  

- 配置编号 **code**、配置名 **name**、详情 **description** 便于在主机配置时下拉选择与说明用途。

- **host_service_credentials**（迁移 **032/033**，功能开关 `credentials_vault_enabled`）
  - 按 **user_id** 存储 sudo、mysql、跳板 SSH 等服务密码；匹配键 `service + address + port + service_username`；**不绑定**操作主机。
  - 字段含 label、notes、password_enc、linked_host_id / linked_credential_id；密码仅可注入不可查询。
  - 密码 **不可查询**；AI 通过 `send_service_password` 在 terminal / ssh_channel / local_terminal 出现密码提示时注入。REST：`/api/service-credentials`。

### 3.3 服务器树与主机

- **host_groups**：id, name, description, **parent_id**（自引用，多级分组）, created_at  
- **hosts**：id, name, host, port, **credential_id**（外键）, description, **aliases**（JSON 数组字符串，多个别名，供 AI list_hosts 搜索与口语称呼）, **remark**（用途说明）, host_type, host_version, host_shell, host_package_manager, created_by, created_at, updated_at  
  - 表中保留 username, auth_type, password_enc, key_path 仅用于兼容旧数据；新主机仅使用 credential_id，登录从 credentials 表取凭证。  
- **host_group_members**：host_id, group_id（多对多）
- **界面**：`/host-groups` 服务器树支持**按主机名、IP、别名、用途说明**搜索（前端过滤，展开匹配路径）。主机详情「详情」Tab 可编辑别名与用途；添加主机表单含别名、用途说明。

### 3.4 服务器维护历史

- **server_maintenance_history**（按 host/port 维度）  
  - id, host (IP), port（可选）, category('install'|'config'|'operation'|'file')  
  - content（文本描述）, file_path（涉及文件路径）, details（JSON 扩展）  
  - created_at, created_by  

便于按 IP 查询历史，供 AI 与用户单独查看、增删改查。

### 3.5 AI 与审批

- **ai_chat_sessions**：id, user_id, **host_id**, title, **session_prompt**, **session_scope**（default/local/integration/**mcp_orchestrate**/**mcp_runtime**）, **low_interaction_mode**, created_at, updated_at  
- **ai_chat_messages**：id, session_id, role, content, created_at。当前仅存 user/assistant 文本消息；tool 调用与执行结果在 agent 循环中仅在内存，未分表存储。提取「仅用户与助手指令」时由 `services/chat_utils.py` 按标记截断助手中的程序输出。  
- **ai_host_knowledge**：按主机维度的 AI 知识（host_id, user_id, content），供 AI 操作该主机时使用。  
- **user_ai_config**（每用户一行）：`active_profile_id` 指向当前激活 Profile；历史 Key/模型列保留兼容。
- **user_ai_model_profiles**（每用户多组）：id, user_id, name, api_key, base_url, model, system_prompt, auto_approve, assistant_enabled, context_size, agent_max_steps, assistant_max_rounds, provider, vision_enabled, ai_output_locale, created_at, updated_at；服务层 `services/ai_model_profiles.py`。
- **settings**：key-value，全局设置；如 ai_auto_approve、ai_assistant_enabled、ai_api_key、**credentials_vault_enabled**（主机服务凭证库，默认 false）等可作为默认值。  
- **ai_pending_actions**（可选）：待用户审批的 AI 动作（命令/SCP），审批后执行并记日志。  
- **辅助 AI 与继续策略**：当用户自己的 ai_assistant_enabled 为 true 时，在运维助手每轮输出后由辅助 AI 判断是否已完成用户目标；未完成则根据会话的 `low_interaction_mode` 决定继续执行或请求用户确认。默认模式下，用户提出新问题或补充原因时优先回答/整合输入，再让用户决定是否继续；低交互模式下减少确认，仅在轮次耗尽、执行失败、缺必要条件或用户显式暂停/停止时停下反馈。

### 3.6 Skills 与最佳实践

- **skills**：id, code, name, description, parameters_schema（JSON），enabled  
- AI 通过 skills 列表获取可调用能力，通过统一入口执行（执行前可走审批逻辑）。  
- **执行与防幻觉**：所有需要真实执行的动作（在主机上执行命令、上传文件、创建/修改/删除资源、向终端发输入等）必须且只能通过 **tool_call** 完成，系统不会根据 AI 的纯文本描述执行任何操作。AI 不得在未发起对应工具调用的前提下在回复中声称「已执行」某操作；此约束写入运维助手与辅助 AI 的 **system prompt**（`api/ai_agent.py` 中 `_build_system_prompt` / `_build_assistant_system_prompt`），可被用户配置的 **ai_system_prompt** 覆盖（仅覆盖运维助手主提示词），以降低幻觉、保证操作可审计可复现。
- **大文本与批量数据策略**：当任务涉及大量日志、长文本、CSV/JSON、目录清单或大批量数据时，AI system prompt 要求优先使用 shell / Python / PowerShell 等脚本化方式处理，避免把全量原文塞入 LLM 上下文。只读统计/提取可直接脚本化；批量修改、覆盖写入、删除等有状态变更需先评估备份或 dry-run，必要时通过 `ask_user_choice` 向用户确认风险。
- **运行时模型身份**：`api/ai_agent._build_active_model_runtime_ctx` 在每轮聊天/集成/后台任务/子 AI/MCP 的 system 中注入当前激活 Profile、model id、provider、上下文预算等，便于 AI 如实回答「你是什么模型」类问题。
- **best_practices**：id, title, category, content, source, created_by, created_at, updated_at；AI 与用户归纳的推荐实现方法，可被 AI 查询与写入。

### 3.7 操作日志

- **operation_logs**：id, user_id, host_id, operation, params, result, details, **source**（如 'ai_agent'|'api'|'manual'）, created_at  
  - 索引：created_at、user_id，便于按时间与用户查询。  
- 所有关键操作（登录、主机/凭证/分组增删改、执行命令、AI 执行、维护历史变更）写入此表。

### 3.8 权限与数据隔离

- **操作日志**：普通用户仅能查看自己的日志；管理员可查看全部，并可按 user_id 筛选。  
- **本地文件系统**：根目录为 **web/fs/当前用户名**；普通用户只能访问自己的目录；管理员可通过 API 参数 `?username=` 访问指定用户目录。  
- **AI 配置**：每用户独立（`user_ai_model_profiles` + 激活项）；每个用户只能读写自己的配置组；系统 settings 中的全局 AI 默认仅管理员可改。
- **个人发信**：每用户独立（user_mail_config），与 settings 全局 SMTP 分离；仅本人可经 API / 界面 / AI 工具配置；定时任务结果邮件使用任务归属用户的个人 SMTP。

## 4. 前端结构

- **技术**：单页应用（SPA），原生 JS + Fetch，无构建；深色科技风样式（`web/css/style.css`）。  
- **入口**：`web/index.html`，脚本 `web/js/app.js`、`web/js/api.js`、`web/js/router.js`、`web/js/utils.js`；终端为 xterm.js（`web/js/xterm.min.js`）+ FitAddon（`web/js/addon-fit.min.js`），终端挂载点绝对定位填满容器，连接后多次 fit 与 ResizeObserver 保证显示区填满黑框。  
- **Web 资源**：全部本地化，不依赖 CDN；聊天 Markdown 基于本地 `markdown-it`（`web/js/markdown-it.min.js`），经 `utils.js` 适配（代码高亮、Callout、Mermaid/Markmap/ECharts、**Three.js / Cannon 三维与物理**、LaTeX fallback）；HTML artifact 资源见 `web/res/manifest.json`；见 `web/README.md`。  
- **文案国际化**：用户可见文案放在 `web/locales/zh-CN/` 与 `web/locales/en/` 的成对 JSON 中（同名文件、相同嵌套键路径）；新增界面文案须两侧同步。校验命令：`python scripts/check_locale_parity.py`（详见 `web/README.md`「文案」一节）。  
- **路由**（`Router.register`，哈希路由）：  
  - `/login`、`/register`：登录/注册  
  - `/dashboard`：仪表盘（主机总数等）  
  - `/hosts`：主机列表；`/hosts/:id`：主机详情（执行命令、**AI 运维**：会话与终端限定当前主机；终端区含**控制台1（AI 使用）**、**控制台2**、**文件系统**、Log 四个 Tab）  
  - `/credentials`：凭证管理（密码型/密钥型 Tab）  
  - `/host-groups`：服务器树（分组树 + 未分组主机，右键菜单、拖放移动；**搜索主机名/IP/别名/用途**）  
  - `/triggered-tasks`、`/scheduled-tasks`：触发任务与定时任务（cron、启用/停用、删除含历史、立即执行）  
  - `/maintenance-history`：维护历史列表与增删改查  
  - `/best-practices`：最佳实践列表与增删改查  
  - `/files`：本地文件系统（web/fs）列表、编辑、上传下载、打包解压  
  - `/ai`：AI 助手页（全局会话；左侧 SSH 终端区含**控制台**、**文件系统**、Log Tab；右侧多 Tab 聊天，流式 SSE、中断、辅助 AI 提示；文件系统 Tab 需先连接主机后加载，切换主机会同步更新）  
  - `/mcp-servers`：个人 MCP 配置（导入/导出、场景开关）  
  - `/skills`：个人 Agent Skills（须 `skills_enabled`；SKILL.md 管理）  
  - `/settings`：系统设置（全局键值表仅管理员；**显示语言**、**我的发信设置**（每用户个人 SMTP，默认关）等）
  - `/model-config`：**模型配置**（每用户多组 AI Profile：新建/编辑/导入导出/设为当前；所有用户可改自己的）
  - `/settings/model-config`：重定向至 `/model-config`  
  - `/users`：用户管理（管理员）  
  - `/logs`：操作日志（按权限过滤）  
- **API 封装**：`api.js` 中 `API.*` 对应后端 REST（Bearer JWT）；`remoteFsList`/`remoteFsRead`/`remoteFsDownload` 为远程文件系统（SSH 主机）；`uploadChatAttachment`/`listChatAttachments` 等为聊天附件；`chatStream` 为 POST /api/ai/chat 的 SSE 流式（可传 **attachment_uuids**），支持 `options.signal` 中断；事件含 `session_id`、`content`、`action`/`tool`（含 `waiting`/`waiting_woken`）、`ui_action`、`assistant_continue`、`requires_user_confirm`、`runtime_control`、`trial_info`、`error`。运行中补充/暂停/停止/唤醒通过 `API.pushAIRuntimeControl` 调用 `/ai/sessions/{session_id}/runtime-control`（`wake` 用于跳过终端轮询倒计时）。
- **流式 Markdown**：`utils.js` 的 `edgeopsRenderStreamIncremental` 在 SSE 过程中分块固化已完成的 Markdown 结构；`finishStreamAndRender` 结束后完整排版并 hydrate 图表。
- **全局能力**：`edgeopsRunUIAction(ui_action)` 供 AI 触发的界面动作（如 `connect_terminal` 自动连接终端）。
- **布局与列表**：左侧系统菜单栏可收窄为仅显示图标，展开/收窄状态持久化（localStorage）；AI 助手、主机 AI、本机 AI 的会话侧栏在失焦、外部点击或 Escape 后自动收回；操作日志等列表表格使用 `.list-table`，时间、用户、操作等列不换行，短内容单行显示，详情列可换行。

## 5. 后端结构

- **入口**：`app.py`（FastAPI），生命周期中 `init_db()`；静态资源挂载 `/static`；SPA 路由统一返回 `index.html`。  
- **模块**：  
  - **api/auth.py**：登录、注册、GET /me；JWT 校验；`get_current_user`、`require_admin`。  
  - **api/users.py**：用户 CRUD、重置密码（管理员）。  
  - **api/credentials.py**：凭证 CRUD；POST /generate-key（RSA/ECC）。  
  - **api/hosts.py**：主机 CRUD；仅 credential_id 或 new_credential；**aliases** / **remark** 序列化与解析；POST /{id}/execute（SSH 命令）；`_resolve_host_auth` 供终端与远程文件系统复用。  
  - **api/host_groups.py**：分组 CRUD；GET /tree（树 + ungrouped_hosts）；分组与主机关联 API。  
  - **api/maintenance_history.py**：维护历史 CRUD；查询支持 host、category。  
  - **api/best_practices.py**：最佳实践 CRUD；GET /categories。  
  - **api/terminal.py**：WebSocket SSH 终端；会话按 (user_id, slot) 存储，支持多控制台；slot 0 为「第一个控制台」，AI 使用的 GET /buffer、POST /send 仅针对 slot 0；首帧 `{ type, host_id, slot? }`。  
  - **api/remote_fs.py**：远程文件系统（SSH 主机）；list/read/download/upload/write/mkdir 等；通过 Paramiko SFTP；路径禁止 `..` 逃逸。  
  - **api/filesystem.py**：本地文件系统根目录 **web/fs/[username]**（按用户隔离）；list/read/write/mkdir/upload/download/pack-tgz/unpack-tgz/delete/copy；管理员可选 `?username=` 访问指定用户目录。  
  - **api/ai_agent.py**：每用户 AI 配置 get/post（读写**当前激活 Profile**）；`/ai/profiles*` CRUD、激活、导入导出；会话 CRUD、clear、会话级低交互开关与 **`chat_mode`（qa/strict/normal）**；POST /chat（SSE 流式，Function Calling + 辅助 AI 驱动循环；支持 **attachment_uuids** 注入 📎 清单；工具执行前走 `chat_mode_gate` / Skills `preToolUse`；严格确认经 SSE `strict_confirm` + `waiting_for_user` 独立模态，用户 choice 后 tool 结果带 `user_decision`）；运行中控制队列支持 supplement/pause/resume/stop/wake/choice；终端轮询等待时 SSE 推送 `waiting`/`waiting_woken`；SSE 使用 JSON keepalive、禁用代理缓冲并对慢工具任务做 shield/异常兜底；单条消息保存上限 AI_MESSAGE_SAVE_MAX（20 万字符）避免长回复截断。  
  - **api/chat_attachments.py**：聊天附件上传/列表/下载/绑定/删除；落盘 `web/fs/<user>/chats/`；kind 含 **document**（Office/PDF，由 MarkItDown 转换）。  
  - **api/ai_artifacts.py**：AI 成果物元数据与下载/预览（与 `create_chat_artifact` 技能配合）。  
  - **api/skills.py**：GET /skills（全局 skills 表，启用技能列表）。  
  - **api/user_mcp_servers.py**：每用户 MCP 配置 CRUD、import、export、test、refresh-tools。  
  - **api/user_skills.py**：每用户 Agent Skills（须 `skills_enabled`）；CRUD、scan。  
  - **api/settings.py**：GET/POST /settings（仅管理员）；GET /logs（普通用户仅自己、管理员可 user_id 筛选）。  
  - **api/batch.py**：批量操作（run_command、scp_push、run_script、restart 等）列表与详情。  
  - **api/scheduled_tasks.py** / **api/triggered_tasks.py**：定时任务与触发任务 CRUD、执行历史、run-now、all-runs 等。  
  - **api/user_mail.py**：GET/PUT **/user-mail-config**，当前用户个人 SMTP（与全局 settings 分离）。  
  - **api/ssh_channel.py**：SSH TTY 通道（HTTP/WebSocket；`/lines` 含 tail_text/pending_partial；Web「SSH通道管理」只读监视）。  
  - **api/local_host.py**：本机管理（仅管理员）。  
  - **api/dashboard.py**：仪表盘统计。  
  - **api/api_tokens.py**：用户 API Token（`eop_`）。  
  - **api/search_config.py**：网页/GitHub 搜索配置。  
  - **api/login_board.py**：登录页匿名留言板（公开 + 管理员审核）。  
  - **api/feedback.py**：系统内用户反馈（用户 + 管理员）。  
  - **api/integration_ops.py** / **integration_mcp.py** / **integration_claw_ops.py**：外部智能体集成通道。

## 7. 接口设计要点（概要）

- **认证**：POST /api/auth/login、register；GET /api/auth/me；Bearer JWT。  
- **凭证**：CRUD /api/credentials；POST /api/credentials/generate-key。  
- **主机服务凭证**：GET/POST/PUT/DELETE /api/service-credentials（元数据；需 credentials_vault_enabled）。  
- **分组树**：GET /api/host-groups/tree；CRUD /api/host-groups；分组与主机关联。  
- **主机**：CRUD /api/hosts（credential_id 或 new_credential）；POST /api/hosts/{id}/execute。  
- **维护历史**：CRUD /api/maintenance-history；查询 host、category。  
- **AI**：会话 CRUD、clear；POST /api/ai/chat（SSE 流式）；POST `/api/ai/sessions/{session_id}/runtime-control`（运行中补充/暂停/恢复/停止）；GET /api/ai/skills。未配置自有 API Key 的用户自动使用系统共享 Key，**默认 2000 次上限**（`SYSTEM_AI_USAGE_LIMIT`）；配置自有 KEY 则不受共享 Key 计数限制；使用共享 Key 时每轮 AI 首条回复前有配额横幅（SSE `trial_info`）；达上限后 `/api/ai/chat` 不 403、改为流式固定文案，summarize 类端点仍 403；管理员可用 `reset_user_system_ai_usage` / `apply_system_ai_config_to_user`。  
- **设置与日志**：GET/POST /api/settings；GET /api/logs。  
- 完整路径、请求体、响应体见 **《API 文档》**（docs/API文档.md）。

## 8. AI 页交互与终端

- **布局**：左侧固定或可收起的 SSH 终端区域（含控制台、文件系统、**SSH通道管理**、Log 等 Tab）；右侧为聊天区，支持多 Tab，每 Tab 对应一个会话。  
- **SSH通道管理 Tab**（AI 助手页 / 主机 AI 页）：  
  - 列出当前用户 **open** 的 `ssh_channel`（主机页仅当前 host）；每个通道一个子 Tab。  
  - **只读** xterm 展示：`GET /api/ssh-channel/{id}/lines?last_n=80` 快照，或 `WS /api/ssh-channel/{id}/ws` **实时监视**（UI 不 send）。  
  - AI 聊天中 `ssh_channel_create` / `close` / `close_batch` 完成后自动刷新列表；用户再次打开该 Tab 时自动与服务端同步。  
  - 帮助：`web/aihelp/ssh-channel.md`。  
- **终端**（Web 控制台）：  
  - 用户可选择已配置主机并连接，终端显示 SSH 输出，用户可输入命令。  
  - 后端提供 WebSocket 接口，将终端 I/O 与 AI 打通：AI 可读取**第一个控制台**（slot 0）内容，并可向该控制台写入命令并执行。  
  - **多控制台**：主机详情页支持「控制台1（AI 使用）」与「控制台2」；连接时首帧可传 `slot`（0/1…），后端按 (user_id, slot) 维护多路会话；GET /terminal/buffer 与 POST /terminal/send 仅作用于 slot 0。  
  - 终端显示区填满容器：挂载点（.ai-terminal-mount）绝对定位铺满 .ai-terminal-container 内容区；使用 FitAddon（可用时）或回退手动计算 cols/rows，配合多次延迟 fit 与 ResizeObserver，使终端宽高与黑框一致。  
- **远程文件系统 Tab**：  
  - 主机详情页与 AI 助手页均提供「文件系统」Tab：左侧目录树（目录在上、文件在下），右侧预览区（文本/Markdown 渲染）、路径栏、刷新、下载；数据通过 /api/remote-fs/list、/read、/download 从当前主机获取。  
  - AI 助手页：需先连接终端并选择主机后才加载文件树；切换主机后再次打开该 Tab 会按新主机同步更新列表。  
- **聊天**：  
  - 会话列表（历史）可展开/收起，支持新建、删除；当前会话消息展示在右侧；单条消息保存上限 20 万字符，加载或流式结束后自动滚动至最后一条，避免长回复展示不全。  
  - 输入框：**Enter 发送**，**Shift+Enter 换行**。  
  - 输入区域提供会话级开关 **「低交互」** / `Low interaction`（默认关闭），以及 **聊天模式** 下拉（问答 / 严格 / 普通，紧挨模型选择、无「模式」标签）。问答模式拦截写操作并展示可复制命令卡；严格模式由平台弹出独立确认模态（允许 / 总是=本会话同工具名 / 拒绝），模型提示与普通模式相同、不感知「严格」；创建/打开终端豁免确认；用户决策写入 tool 返回的 `user_decision`；普通模式保持默认并仍评估 Skills Hook。  
  - 流式执行期间输入区域切换为紧凑运行中控制条，支持「补充并调整」「暂停」「停止」；补充信息可在工具执行中进入后端 runtime control 队列，下一轮或当前慢工具等待间隙被消费。进入运行态时焦点自动落到补充输入框，完成后焦点回到普通聊天输入框。
  - 聊天正文采用本地 **markdown-it** 渲染（`formatMarkdown`）：自动剥离 HTML 注释、修正安全 HTML 标签空格、压缩无意义空行、渲染标题/列表/表格/代码高亮/diff/log/tree/http/Callout，并支持 `$...$`、`$$...$$` 与裸 LaTeX 行的公式 fallback；AI system prompt 也会约束输出使用标准 Markdown、公式定界符和简洁格式。
  - 当 AI 决定执行命令或 SCP 时：若未开启自动同意，则前端弹出审批；用户同意后后端执行并写日志与维护历史。  
  - **辅助 AI**：开启后，用户发出一条指令即由运维助手执行；辅助 AI 在每轮输出后判断是否需继续，并自动注入引导语驱动下一轮，直至完成或需用户输入；前端可显示「[辅助AI] 继续执行…」等提示；用户可通过中断按钮强行停止。

## 9. 安全与合规

- 密码、私钥等敏感字段加密存储（如使用配置密钥加密后存库）。  
- 凭证与主机分离，避免在主机列表中暴露明文凭证。  
- 所有操作落操作日志，便于审计。
