# 毛竹 并发访问与扩展说明

面向「多用户同时使用」时的架构现状、异步/线程/子进程分工，以及后续演进建议。与 [开发与完善建议.md](开发与完善建议.md)、[技术栈说明.md](技术栈说明.md)、根目录 [README.md](../README.md) 互补。

**当前版本**：v1.3.6；数据库 **schema v31**（迁移 **000–030**）。

---

## 1. 总体模型

| 层次 | 说明 |
|------|------|
| **Web 框架** | FastAPI + Uvicorn，**异步 ASGI**。HTTP/WebSocket 在事件循环上调度，等待 I/O 时让出执行权。 |
| **推荐部署** | **`EDGEOPS_WORKERS=0`（单进程，默认）**：与 SQLite 全局连接、内置**定时任务调度器**（`services/scheduler.py`）、进程内 **SSH Channel** 状态、反馈/留言邮件**去抖字典**一致。 |
| **多 worker 风险** | `WORKERS≥1` 时：定时任务可能**重复触发**、各进程独立去抖（邮件通知可能多发）、SSH 通道不跨进程共享、SQLite 写竞争加剧。**Windows 下强制单进程。** |
| **横向扩展** | 多实例前需：**可共享或替代的 DB**、**全局单点调度**、**SSH 会话粘性**（或接受会话绑单实例）、**`web/fs` 共享存储**（附件、Skills、chats）。 |
| **探活** | 现有 **`GET /api/version`**（无认证）；无专用 `/health`。负载均衡可先用 version，或自行加 DB ping 端点。 |

## 2. 已采用的异步与非阻塞实践

- **对外 HTTP（LLM、部分 MCP HTTP）**：`httpx.AsyncClient` 等，避免阻塞事件循环。
- **阻塞型系统调用**（Paramiko、SFTP、主机探测、MarkItDown 转换、部分 MCP stdio 交互）经 **`asyncio.to_thread(...)`** 放入默认线程池，典型位置包括：
  - `services/ssh_client.py`
  - `api/terminal.py`（WebSocket SSH）
  - `api/hosts.py`、`api/remote_fs.py`、`api/ssh_channel.py`
  - `services/ssh_channel_manager.py` / `ssh_channel_service.py`
  - `services/markitdown_convert.py`（聊天附件 Office/PDF）
  - `services/user_mcp_client.py`（个人 MCP 连接探测等，视 transport 而定）
- **子进程**：本机脚本等使用 **`asyncio.create_subprocess_*`**（如 `api/local_host.py`）；个人 MCP **stdio**  transport 在服务端拉起子进程，需注意并发连接数与资源上限。
- **SSE 聊天**：多用户可同时持有 `/api/ai/chat` 长连接；单进程内由 asyncio 并发，CPU 密集渲染在浏览器端。

多名用户同时开终端、跑 AI、上传附件时，长时间 SSH/磁盘/转换型工作不应卡死整个事件循环（前提是路径已走 `to_thread` 或异步 I/O）。

## 3. 数据库与多人并发（SQLite）

- 使用 **全局单连接 `aiosqlite`**（`database.get_db()`），SQLite 语义下**写操作串行**；多读在 WAL 下可并行。
- 启动时 `apply_sqlite_concurrency_settings`：
  - **`PRAGMA journal_mode=WAL`**（默认开，`EDGEOPS_SQLITE_WAL=false` 可关）
  - **`PRAGMA busy_timeout`**（默认 5000 ms，`EDGEOPS_SQLITE_BUSY_TIMEOUT_MS`）
  - **`PRAGMA synchronous=NORMAL`**（与 WAL 搭配）
- **定时任务抢占**：调度循环在 **`BEGIN IMMEDIATE`** 事务内更新 `is_running`，减轻多协程/误配多进程下的重复执行（仍无法替代「只跑一个调度进程」）。

**何时考虑换库**：持续高并发写（大量聊天落库、批量任务、操作日志暴涨）或需多实例写同一库时，评估 **PostgreSQL** 等 + **连接池** + 按请求/短生命周期连接；需分阶段改造 `database/` 访问层。

**迁移**：老库启动时顺序执行 `database/migrations/` 直至 **v31**；全新库可用 `scripts/bootstrap_fresh_db.py` 或 `fresh_install.sql`。

## 4. 线程 vs 子进程（设计原则）

| 场景 | 建议 |
|------|------|
| **Paramiko / 同步库 / MarkItDown** | **线程池**（`asyncio.to_thread`） |
| **用户本机脚本、隔离执行** | **子进程**（已有）；设超时与资源上限 |
| **个人 MCP stdio** | 子进程 + 线程内 I/O；限制每用户并发连接与命令白名单策略 |
| **CPU 重批处理** | 独立 Worker 队列或子进程，避免拖垮 API 进程 |

不建议为每个 HTTP 请求新建进程；**优先 async I/O + 线程池卸载阻塞**。

---

## 5. 与功能相关的并发注意点

| 功能 | 说明 |
|------|------|
| **定时/触发任务** | 单进程内调度；多实例必须外置锁或只在一台跑 scheduler |
| **反馈/留言邮件通知** | `feedback_notify` 等使用**进程内** 30s 去抖；多 worker/多实例各自去抖，可能重复发信 |
| **系统共享 AI Key 计数** | `user_system_ai_usage` 表级更新，高并发下依赖 SQLite 串行写 |
| **个人 Skills 扫描** | 磁盘遍历 + DB upsert，宜避免多用户同时全量 scan 高峰 |
| **静态资源** | `/static`、`/intro` 由 Starlette 提供，只读，易水平扩展（注意 `web/fs` 写路径需共享卷） |
| **JWT 滑动刷新** | 无状态；多实例无需会话粘滞（除 WebSocket 终端/Channel） |

## 6. 后续可做事项（按优先级）

1. **保持单进程 + WAL + busy_timeout**（已默认），监控是否仍频繁 `SQLITE_BUSY`。  
2. **热点审计**：残留同步 `requests`、大文件同步读写在 API 协程内直接执行的路径，改为 `to_thread` 或流式。  
3. **探针**：实现 `/health`（DB `SELECT 1`、可选磁盘空间检查）。  
4. **中大规模**：PostgreSQL、连接池、操作日志归档；多实例 + **Redis 分布式锁** 管定时任务。  
5. **只读扩展**：静态与 `/intro` 可 CDN；API 层有状态部分需粘性或共享存储。
