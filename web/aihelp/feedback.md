# 反馈与登录留言板

毛竹 内置两套反馈通道：

- **登录页留言板**：登录页右下角的可折叠浮窗，**任何人**（无需登录）都可以匿名留言；管理员审核后可选择是否公开展示。
- **系统内反馈**：登录后侧边栏「反馈」菜单，**已登录用户**向管理员提交反馈，管理员可回复 / 忽略 / 撤回回复，用户也可在管理员尚未回复时撤回或修改。

两者内容均为 **Markdown** 格式，UI 内建预览渲染。

---

## 1. 登录页留言板（匿名）

### 1.1 适用场景

- 未登录的访客想给系统留言（如安装求助、忘记账号、功能建议等）。
- 管理员希望把一部分留言（含管理员回复）作为「公开通告」呈现在登录页，向所有访客可见。

### 1.2 用户操作步骤

1. 打开登录页，右下角有「💬 留言板」浮窗，点击展开。
2. 上半区是**已审核公开**的留言列表（含可见的管理员回复）。
3. 下半区是留言表单，依次填：
   - **昵称**（可选，匿名时显示「匿名访客」）
   - **内容**（Markdown）
   - **数学验证码**（防机器人，与登录用同一类型 `a+b=?`）
4. 点击「提交」即可。提交成功后状态默认是 **待审核**，不会立即出现在公开列表中。
5. **限频**：同一 IP **60 秒内最多 3 条 + 24 小时内最多 20 条**；触发限频会返回 429 并提示稍后再试。

### 1.3 管理员操作步骤

1. 登录后进入侧边栏「反馈 → 登录页留言」（或访问 `/feedback/admin/login-board`）。
2. 顶部按状态过滤：**待审核 / 已通过 / 已隐藏 / 全部**。
3. 列表中每条留言可执行：
   - **通过并展示**（`status=approved` + `show_on_login=1`）—— 公开到登录页
   - **通过但不展示**（`status=approved` + `show_on_login=0`）—— 留档但不公开
   - **隐藏**（`status=hidden`）—— 从列表里下沉，不公开
   - **回复**（写 Markdown 回复，可独立勾选「在登录页显示这条回复」）
   - **删除**—— 整条删除（含其下所有管理员回复，级联）
4. 留言与管理员回复都用 `parent_id` 串成同一条线，删除原留言会一并清除回复。

### 1.4 与 AI 的配合

- 当前版本登录页留言板的审核 / 公开 / 回复 / 删除**没有**专用 AI 工具，请直接在 `/feedback/admin/login-board` 后台操作。
- AI 重点接入的是「系统内反馈」侧的工具，详见本帮助文档第 3 节。

### 1.5 风险提醒

- 任何人都可以提交，**审核前不可见**，但仍占用数据库空间；如遭遇大量垃圾，可临时把 `services/feedback.py` 顶部的 `ANON_RATE_LIMIT_*` 常量收紧（重启生效），或在管理后台批量删除 / 隐藏。
- 公开展示的内容会被搜索引擎抓取——管理员审核时**避免**通过含个人隐私、敏感配置或攻击性内容的留言。

## 2. 系统内反馈（已登录用户）

### 2.1 适用场景

- 用户在使用过程中遇到 bug、功能建议、技术求助，希望直接送达管理员，并能持续追踪状态。
- 用户希望收到管理员的针对性回复（多轮）。
- 管理员需要按未读 / 未回 / 已忽略等维度集中处理反馈。

### 2.2 用户操作步骤

1. 登录后点击侧边栏「反馈」（路由 `/feedback`）。
2. **提交新反馈**：
   - 标题（可选）
   - 内容（Markdown，支持代码块、列表、链接、`![](图片url)` 等）
   - 点击「提交」即创建一条 `status=open` 的反馈。
3. **查看自己的反馈列表**：按时间倒序，每条显示标题 / 摘要 / 状态 / 最近回复时间 / 未读管理员回复角标。
4. **状态机**（存活状态只有三种）：
   - `open`：已提交、**且尚无任何管理员回复**——**用户可编辑或撤回**。
   - `replied`：管理员已回复——**用户不能再编辑或撤回**，可继续追加新内容（前端会用一条新的反馈承载，避免改写历史）。
   - `ignored`：管理员标记为忽略——前端置灰，用户仍可读，但不再期望回复。
5. **撤回**：在 `open` 状态且无任何回复时点击「撤回」会**物理删除**这条反馈（数据库不保留 `withdrawn` 状态行），列表里立刻消失。

### 2.3 管理员操作步骤

1. 进入侧边栏「反馈」（路由 `/feedback/admin`，仅管理员可见）。
2. 顶部 Tab 按状态过滤：**未读 / 待处理 / 已回复 / 已忽略 / 全部**；侧边栏菜单旁有**未读角标**实时更新。
3. 单条操作：
   - **回复**（写 Markdown 回复，发送后反馈状态自动从 `open` 变 `replied`，可发多条）
   - **修改回复**（PATCH）——可修订自己的回复内容
   - **撤回回复**（DELETE）——若该条是最后一条管理员回复，反馈状态会**回退到 `open`**，用户因此恢复编辑/撤回权限
   - **忽略**（`status=ignored`，可再「重新打开」回到 `open`）
   - **重新打开**（从 `ignored` / `replied` 转回 `open`）
   - **标记已读** / **全部标已读**——清未读角标
4. **邮件通知开关**（重要）：
   - 在「系统设置 → 反馈邮件通知」（仅管理员可见）勾选「**新反馈到达时邮件通知所有管理员**」。
   - 默认 **关闭**；勾上后任意用户提交新反馈时，系统用**全局 SMTP** 给所有管理员（绑定了邮箱的）发简短通知；带 30 秒去抖，避免短时间内 N 条反馈淹没收件箱。

### 2.4 与 AI 的配合

- 用户可对 AI 说「帮我反馈一下：xxx 功能在 xxx 情况下报错 …」——AI 调 `submit_feedback` 即可。
- 用户可对 AI 说「我之前的反馈处理到哪了」——AI 调 `list_my_feedback`。
- 管理员可对 AI 说：
  - 「列一下未读的用户反馈」「按批查看，最多 10 条」——`list_user_feedback_admin(status=unread, limit=10)`
  - 「打开第 12 条看看」——`get_user_feedback_detail(id=12)`（自动标已读）
  - 「用一句中文回复第 12 条，告诉用户已经修复了」——`reply_user_feedback_admin(id=12, content=...)`
  - 「忽略第 7 条」——`ignore_user_feedback_admin(id=7)`
  - 「把所有未读的标已读」——`mark_all_user_feedback_read()`
- 详见下一节「AI 工具」。

### 2.5 风险提醒

- 用户提交后管理员若回复，用户便**不能再撤回原文**——这是为了保留对话上下文；如果用户希望撤回，请先和管理员沟通让管理员先 `withdraw_reply`，反馈会回到 `open` 再撤回。
- 删除一条反馈是**硬删除**（含其下所有管理员回复），管理员删除前请确认。

## 3. AI 工具一览（与本功能相关）

| 工具名 | 角色 | 作用 |
|---|---|---|
| `submit_feedback` | 任意登录用户 | 提交一条新反馈 |
| `list_my_feedback` | 任意登录用户 | 列我提交的反馈 |
| `list_user_feedback_admin` | 仅管理员 | 列全员反馈，支持按 `status` / `unread` / `limit` / `offset` 过滤分批 |
| `get_user_feedback_detail` | 仅管理员 | 取单条反馈详情（含管理员历次回复），**自动标已读** |
| `reply_user_feedback_admin` | 仅管理员 | 给某条反馈写 Markdown 回复，状态变 `replied` |
| `ignore_user_feedback_admin` | 仅管理员 | 把某条反馈标为 `ignored` |
| `mark_all_user_feedback_read` | 仅管理员 | 把当前管理员未读的反馈一次性全部标已读 |

> **登录页留言板**侧目前**未提供专用 AI 工具**——审核、公开、回复、删除等操作请直接在管理员后台 `/feedback/admin/login-board` 中点击完成。后续可按需扩展。

## 4. 常见问题

### 4.1 我的留言怎么没在登录页出现？

匿名留言**默认是 `pending`** 状态，需要管理员审核并勾选「显示在登录页」后才会出现。AI 留言或测试留言也一样要审核。

### 4.2 我作为用户，提交反馈后想改内容，发现按钮灰了

说明**管理员已经回复**——为了保留对话上下文，原始反馈内容不允许再改；可以另起一条新反馈补充。如确实需要改，可以请管理员先撤回最新回复，状态回到 `open` 后再编辑。

### 4.3 管理员同时收到 10 条新反馈，邮箱会被打爆吗？

不会。`feedback_notify` 模块带 30 秒去抖：在窗口内只发一封"汇总型"通知，之后每 30 秒最多一封；即使开关常开也不会刷屏。如果你想完全停用，去「系统设置 → 反馈邮件通知」取消勾选即可。

### 4.4 留言板被刷怎么办？

匿名提交带 IP 限频（**60 秒内最多 3 条 + 24 小时内最多 20 条**，常量在 `services/feedback.py`）；如遇定向骚扰，可临时调小常量后重启，或在管理后台批量隐藏 / 删除。极端场景可在反向代理层加 IP 拉黑。

## 5. 与维护历史 / 最佳实践的关系

- 反馈与留言板**不是**维护记录；它面向"用户和管理员之间的双向沟通"。
- 如果某条反馈中讨论出来的方案值得沉淀，建议管理员手工或让 AI 把结论同步到 [maintenance.md](maintenance.md) 所述的「维护历史」或「最佳实践库」中，让团队后续可以复用。
