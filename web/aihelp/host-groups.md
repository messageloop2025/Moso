# 服务器树与主机分组步骤手册

主机分组用于把多台主机组织成树形结构，也就是常说的“服务器树”。它的核心价值不是展示，而是为了后续更方便地：

- 快速找到主机
- 统一管理同类服务器
- 做批量任务
- 让 AI 更容易理解主机范围

---

## 1. 先理解分组规则

在使用前，先理解这几条基本规则：

- 分组支持多级结构，可设置父分组
- 每台主机同一时刻通常只属于一个分组
- 分组有创建者归属
- 普通用户只能操作自己有权限的分组和主机
- 管理员可查看和操作更多内容

### 这意味着什么

- 服务器树不仅是视觉分层，也是权限和批量范围的一部分
- 分组建得越清晰，后续批量任务越不容易选错

---

## 2. 推荐的分组思路

建分组前，先决定你要按什么维度组织服务器。

### 常见分法

- 按环境：生产 / 测试 / 开发
- 按业务：网关 / Web / API / DB / 缓存
- 按区域：华东 / 华南 / 香港 / 海外
- 按客户：客户A / 客户B / 客户C
- 按团队：平台组 / 应用组 / 运维组

### 推荐做法

- 先确定一个主维度
- 再在下一层补充次维度
- 不要一开始就建太深

### 示例结构

```text
生产
  Web
  API
  DB
测试
  Web
  API
  DB
```

或者：

```text
支付业务
  生产
  测试
商城业务
  生产
  测试
```

## 3. 新建分组

### 适用场景

- 准备整理已有主机
- 为某个业务建立新的服务器树
- 为批量任务提前规划范围

### 操作步骤（界面：服务器树页 `/host-groups`）

1. 进入左侧菜单 **「服务器树」**（`/host-groups`）。
2. 使用 **右键菜单「添加分组」**（中英文界面文案一致，英文为 *Add group*）：
   - 在 **某个分组** 上右键 → 输入分组名 → 将在该分组下创建 **子分组**（自动带上父级 `parent_id`）。
   - 在 **「未分组主机」区域**（未点在具体主机行上）或 **树区域空白处** 右键 → 输入名称 → 创建 **顶级分组**（无父级）。
3. 同一菜单中仍可 **刷新** 树；在分组上还可 **重命名 / 删除** 等（需有相应权限）。

说明：描述字段可在后续通过重命名流程或 API 补充；界面快捷创建以 **名称** 为主。

### 命名建议

- 用短而明确的名称
- 名称体现一个维度
- 不要把多种含义混在一起

推荐：

- `生产`
- `测试`
- `API`
- `华东`

不推荐：

- `生产华东支付API临时节点`

## 4. 建立多级分组

多级分组适合主机较多的场景，但不建议过深。

### 推荐步骤

1. 先建立顶层分组（例如在空白处或未分组区域右键 **「添加分组」**）
2. 再在该分组上右键 **「添加分组」** 建立二级分组
3. 如果确实有必要，再在子分组上继续添加子级（仍建议控制总深度）

### 推荐层级

- 小规模环境：1 到 2 层
- 中等规模环境：2 到 3 层
- 非常复杂的环境：一般也尽量控制在 4 层以内

### 为什么不要太深

- 难找
- 难拖拽
- 批量选择不直观
- AI 和用户都更容易理解错误

---

## 5. 把主机加入分组

### 操作方式

- 通过页面选择主机加入分组
- 或在服务器树中拖放主机到目标组

### 推荐步骤

1. 先确认目标分组是否正确
2. 再确认主机应该归属哪个层级
3. 把主机加入分组
4. 再刷新检查树结构是否符合预期

### 注意

如果主机已经在别的组中，加入新组后通常会从旧组移出，因为同一时刻只属于一个分组。

---

## 6. 拖放分组与主机

服务器树支持拖放，适合做结构整理。

### 主机拖放

适合：

- 把主机移动到另一个业务组
- 把主机从测试组移到生产组
- 把主机归到更准确的分类下

### 分组拖放

适合：

- 把一个组变成另一个组的子组
- 把一个子组拖到空白处变成顶层组
- 重新整理树结构

### 推荐操作步骤

1. 先想清楚目标位置
2. 再执行拖放
3. 拖放后检查结构是否正确
4. 再刷新页面确认状态保持正常

### 注意事项

- 分组必须遵循归属规则
- 同一用户下的组和主机整理起来最安全
- 如果是管理员整理跨用户数据，更要先确认归属逻辑

---

## 7. 编辑分组

当名称、描述或层级不合理时，可以编辑分组。

### 适合编辑的场景

- 组名不清晰
- 描述缺失
- 分层设计不合理

### 推荐步骤

1. 先确定为什么要改
2. 再修改名称、描述或父分组
3. 保存后检查树结构
4. 如涉及批量任务使用的组，建议通知相关使用者

---

## 8. 删除分组

删除分组不会删除主机本身，但会影响树结构和批量选择范围。

### 删除前建议先确认

- 组下是否还有主机
- 这个组是否仍被批量操作依赖
- 是否只是名字不合适，其实更适合编辑而不是删除

### 删除后的常见影响

- 分组从树中移除
- 组内主机关联会被清理或失去原层级归属
- 主机本身不会被删除

---

## 9. 用分组做批量任务

这是分组最重要的使用场景之一。

### 推荐步骤

1. 先确保分组里的主机都是同类目标
2. 在批量任务中选择“按分组”
3. 选中目标分组
4. 小范围验证后再执行大范围任务

### 为什么要这样做

因为如果一个分组里混入了不应执行的主机，批量任务就容易误伤。

---

## 10. 管理员与普通用户看到的区别

### 普通用户

- 通常只能看到和操作自己有权限的分组与主机
- 不应把别人的主机拖入自己的组

### 管理员

- 可查看更完整的服务器树
- 可看到所有用户的数据范围
- 在整理结构时要特别注意所有权和归属规则

---

## 11. 推荐的分组维护习惯

### 习惯一：一组只表达一个逻辑

例如这个组表达“环境”，就不要再同时表达“地域”和“角色”。

### 习惯二：不要让顶层过多

顶层太多时，服务器树会变乱。能收敛到几个主维度最好。

### 习惯三：定期清理废弃组

临时组、空组、测试结束后的组建议及时整理。

### 习惯四：批量任务前先检查组内容

特别是生产环境，永远不要默认相信组内容没有漂移。

---

## 12. 常见问题

### 12.1 为什么主机不在预期分组里

优先检查：

- 是否被拖到了别的组
- 是否加入新组后从旧组被移出
- 是否刷新后状态变化

### 12.2 为什么不能把某个组拖到另一个组

优先检查：

- 是否违反归属规则
- 是否权限不足
- 是否存在层级冲突

### 12.3 为什么批量任务范围不对

优先检查：

- 目标分组里是否混入了不相关主机
- 是否选错了上层组
- 是否权限过滤了部分主机

---

## 13. 推荐的服务器树搭建流程

如果你要从零开始整理一套服务器树，建议按这个顺序：

1. 先确定主维度
2. 建立顶层组
3. 建立二级组
4. 再把主机逐步归位
5. 最后用批量任务验证范围是否符合预期

### 一个实用方法

先不要急着把所有主机都拖进去，可以：

1. 先整理一部分代表性主机
2. 验证结构和批量范围
3. 再逐步完成全量整理

这样能减少返工。
