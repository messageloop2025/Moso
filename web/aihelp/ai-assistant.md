# AI 助手使用与配置

毛竹 内置 AI 运维助手，可通过自然语言驱动主机管理、执行命令、上传文件、批量任务、查询维护历史与最佳实践等。

---

## 使用方式

- **全局 AI**：在「AI 助手」页发起对话，可操作当前用户有权限的任意主机、分组、凭证等。
- **主机维度 AI**：在某一主机的会话下，AI 仅针对该主机操作（如仅在该机执行命令、上传、查看该机维护历史等），便于聚焦单机运维。
- **外部智能体**（OpenClaw / Hermes / Cursor MCP）：不经过本页聊天 UI，使用 **个人 API Token** 与集成接口；见 [external-integration.md](external-integration.md)。
- **扩展本页 AI 能力**（可选）：
  - **个人 MCP**（`/mcp-servers`）：把第三方 MCP **工具**并入对话；见 [external-integration.md](external-integration.md)。
  - **个人 Agent Skills**（`/skills`，须管理员开启）：Cursor 格式 `SKILL.md`，**渐进式披露**（默认仅目录，按需 `get_user_skill`）；也可在对话中创建/导出/导入。见 [external-integration.md](external-integration.md)。
- **建议先读**：如果你想系统掌握“先做什么、后做什么、怎么避坑”，建议再配合阅读 [operations-manual.md](operations-manual.md)。

### 回复语言、界面语言与流式规划

- **语言优先级**（与后端 `resolve_output_language` 一致）：用户在本条消息里**显式**要求某种语言（如「用英文答」）优先 → 否则尽量与**本条用户输入**的主要语言一致 → 若无法判断，则依次采用 **「系统设置 → 我的 AI 配置」中的「回复语言」** → **站点全局「回复语言」** → **当前界面语言**（「显示语言」选「跟随浏览器」时由浏览器/系统决定；否则会固定为你在设置里选的 zh-CN 或 en）。
- 前端请求聊天接口时会带上当前**有效界面语言**（`ui_locale`），供上述链路在「个人/站点均未单独设默认回复语言」时回退，与界面保持一致。
- **流式「思考 / 规划」**：模型在工具调用前输出的步骤说明、推理片段等，系统提示中要求与**最终答复**使用同一套自然语言策略，减少中英无故混用。工具名、路径、命令与原始日志不强行翻译。

### 上下文与长结果

- 会话**历史条数与长度**会按预算截断；**主机列表 / 分组 / 终端摘要**等也会按比例压缩，优先保留与当前问题更相关的部分。
- 单条**工具返回**过大时，完整内容会落到你的 `chats/…/spill/` 等位置，消息里仅以 `[[EDGEOPS_CHAT_DATA ...]]` 哨兵 + 摘要呈现；需要逐行核对或全量统计时，应让 AI 使用 **`read_chat_data`**（及附件场景的 **`read_chat_attachment`**）分段读取，避免仅凭摘要断言「已全部处理」。

### 失败、超时与排障

- 若上游 **HTTP 超时**或异常，服务端会将 **`[错误] …` 说明**与本轮已采集的 **工具/推理轨迹（TOOL_TRACE，与成功时相同格式）** 一并写入助理消息，刷新或重新进入会话后仍可在历史里展开查看「做到哪一步、调了哪些工具」。
- 读超时默认 **240s**，同一轮 LLM 请求默认在超时后**自动再试 3 次**（共 4 次）；可通过部署环境变量 **`EDGEOPS_AI_CHAT_HTTP_READ_TIMEOUT_SEC`**、**`EDGEOPS_AI_CHAT_LLM_TIMEOUT_RETRIES`** 调整。
- 生成长 **HTML 报告**时，优先 **`fs_write_file` / `create_chat_artifact` 分段或多文件**，避免单次工具参数塞入过大正文导致网关或模型侧不稳。
- **Office/PDF 附件**：模型不会自动「看见」二进制正文，需让其调用 **`read_chat_attachment(uuid=…)`**；若 Docker 部署后仍无法分析，确认镜像已 **`--build` 重建**且含 `markitdown`（见 [Docker部署.md](../../docs/Docker部署.md)）。

## 能力概览

- 列出/查询主机、凭证、分组、维护历史、最佳实践。
- 在指定主机上执行 SSH 命令（ssh_execute）、向已打开的控制台发送输入（send_to_terminal）。
- 上传/下载文件：小文件用 scp_push / scp_pull（SFTP）；大文件或目录用 scp_transfer（系统 scp 流式传输，支持 recursive、legacy_rsa）。
- 创建/管理批量任务（batch_create、list、detail、cancel、retry）。
- 管理主机知识（get/update/append_host_knowledge）：记录该主机上的账户、密码、路径等机密信息，供 AI 在操作该主机时使用（如 sudo 密码），**不会在回复中原文展示**。
- **主机级 AI 提示词**（get/update/append_host_prompt）：按「用户 × 主机」独立保存，描述该主机**独有的规则 / 能力 / 工具链 / 配置**（如已装 gh cli、cursor cli、opencode；数据目录约定；禁忌操作等）。主机维度会话中会自动注入 system 提示；主机分享给其它用户时不共用。
- **跨主机搜索能力**（search_hosts_by_prompt）：在 AI 助手或主机聊天中可问「帮我找一下装了 gh cli 的主机」「哪些机器配了 cursor cli」等，AI 会按关键字/正则搜索当前用户维护的主机级提示词，支持按分组（group_id）或标签（tag_ids）限定范围。
- **主机能力画像**（probe_host_capabilities / get_host_capabilities）：对一台主机说「画像一下」「看看这台机有啥」，AI 会一次 SSH 自检 OS、硬件、以及近百种常用 CLI（云 CLI 如 aliyun/aws/gcloud/kubectl/terraform；AI CLI 如 cursor-agent/opencode/aider/claude/codex；安全/渗透类如 nmap/nikto/sqlmap/hydra/hashcat/msfconsole/tshark；语言运行时/DevOps/数据库客户端），将结构化画像以 Markdown 写入主机级提示词的哨兵块内（`<!-- EDGEOPS:HOST_PROFILE v1 -->`），**用户在哨兵之外手写的规则不会被覆盖**；默认 24 小时内复用缓存。画像完成后，后续 AI 规划"用 cursor-agent 改代码、用 aliyun 管云资源、在 Kali 上做渗透"等都会基于真实能力来决策，避免误调用不存在的工具。也可对 AI 说「哪些机器装了 nmap」「哪些机器有 cursor-agent」，结合上一条的 `search_hosts_by_prompt` 就能直接检索到这些能力标签。
- **子 AI 委派**（delegate_to_cli_agent）：当目标主机装有其它 AI 代理 CLI（cursor-agent / opencode / aider / claude / codex / goose / cline / llm）时，对 AI 说「让 cursor-agent 把 /srv/myapp 的登录改成 JWT」「让 aider 给这段代码加测试」「用 opencode 在那台机跑 lint+fix」，毛竹 的主 AI 会：(1) 读主机能力画像确认目标 agent 已安装；(2) 弹出 `ask_user_choice` 让你确认 agent / 任务 / 工作目录 / 模型；(3) 你点确认后才通过 SSH 一次性非交互调用子 AI；(4) 子 AI 跑完，若工作目录是 git 仓库，主 AI 会自动把**改动文件清单 + 增删行 + 前 4000 字 unified diff** 复述给你，让你决定是否保留或 `git reset` 回滚。所有子 AI 的 `stdout` 与错误会作为工具结果返回给主 AI，主 AI 再用自然语言总结。把 API Key（如 `CURSOR_API_KEY`/`OPENAI_API_KEY`）作为 `env` 参数传入；审计日志**只记 key 名不记 value**。后台定时任务（task scope）下不需要二次确认（由任务本体授权）。
- **多步编排**（delegate_chain，含跨主机）：一句话级的"流水线"——你说「让 cursor-agent 改完再自动跑 pytest，失败就让它按报错修一遍」「nmap 扫完让 llm 总结漏洞」「装完依赖歇两秒再验证版本」；**多主机场景**也 OK：「让 A 机上的 cursor-agent 改代码，然后 rsync 同步到 B 机、在 B 机跑集成测试、最后在 C 机部署」，一条链就能写完。AI 会把整条流程打包成一次 `delegate_chain` 调用：每步可以是子 AI（`delegate`）、普通命令（`ssh`）或等待（`sleep`），并通过 `{prev_stdout}` / `{prev_stderr}` / `{prev_exit_code}` 把上一步结果喂给下一步；分支用 `when=on_success / on_failure / always`（如"pytest 失败时 cursor-agent 才修复"）；每步可写 `host_id` 指定执行主机。含写类委派的链会**一次性**让你确认整条链的所有步骤（卡片里会展示每步在哪台机上跑），确认后整体执行，返回每步的 stdout 预览、退出码、git 改动统计、`host_label` 与整体 summary；每台涉及的主机都会各自留一条审计与任务日志。后台定时任务里最推荐用它——"构建机→测试机→生产机"的整条 CI/CD 写进任务定义，跑起来一步不用盯。
- **流式进度**：上面那些编排跑起来以后，**不用等整条链跑完**。前端工具卡底下会实时滚动每一步的开始 / 结束标志、每行 stdout/stderr、子 AI 的每行输出（最多展示 40 行），你能看到 "▶ [1] build on build-01" → `[stdout] Compiling...` → `✓ [1] build on build-01 12.3s` → "▶ [2] pytest on test-02" 这种"真时间线"。长链里某一步卡住也能立刻看出来，不用猜。
- **工作流模板**（save/list/run_workflow_template）：跑完一条满意的链对 AI 说「把刚才这条链存一下，叫 daily-deploy」——它会把原 payload 存进「AI 编排工作流模板」，里面易变的字段（目标分支、构建 tag、主机 ID 等）可被写成 `${var}` 占位符。以后直接说「跑一次 daily-deploy，branch 用 release/v2」即可，AI 先用 `dry_run` 给你展开预览，确认后执行；所有安全门禁（画像校验 / 写类确认 / 访问控制 / 审计 / 流式进度）和第一次跑时完全一致。模板默认私有，也可设 `visibility=org` 让同一个 毛竹 实例里的其他用户复用。
- **内部 AI 递归**（delegate_to_edgeops_ai）：当任务需要"独立上下文 / 独立身份"时——比如「把刚才那堆告警整理成一份运维周报」「让另一个 AI 审查你刚写的这段 bash 脚本」——主 AI 会用 `delegate_to_edgeops_ai` 起一个**本机内部**的子 AI 对话（同一份 LLM 账号 + 独立 system_prompt + 工具白名单），跑完把 Markdown 结论回传。这个子 AI 不会出这台 毛竹，不走 SSH，也不改任何主机；默认只给它读类工具，硬限制递归深度=2 防止无限套娃。和 `delegate_to_cli_agent`（把任务扔给远端 CLI）互补。
- **多主机生命周期联动（开发 / 发布 / 运维 / 反馈）**：毛竹 的 AI 助手是**多主机原生**的——同一个会话里你可以一句话让 AI 同时驱动 N 台机器完成一次完整的「开发 → 发布 → 运维 → 反馈」闭环。典型说法：「让 dev-01 的 cursor-agent 按 SPEC.md 实现 jwt-login；过了就去 build-02 打 docker tag v2.3.0，把镜像推到 prod-03 热更新；等 5 秒让 monitor-04 拉 P99；最后让子 AI 写一份中文周报发 oncall@co.com」。AI 会：(1) 依次对涉及主机做能力画像；(2) 组装一条 `delegate_chain`（每步带 `host_id`，用 `when=on_success/on_failure` 做条件、`{prev_stdout}` / `{prev_stderr}` 喂数据），**整条链一次性弹按钮让你确认**（卡片标出每步在哪台机）；(3) 按台流式推进度；(4) 跑完顺势用 `delegate_to_edgeops_ai` 起子 AI 写 Markdown 报告，再 `send_email` 送 oncall；(5) 满意了对 AI 说「存成 `release-v2` 模板，branch/build_tag 变成 `${var}`」，以后一句 `run_workflow_template` 就能复现。跨机中继用 `transfer_file_between_hosts` / `relay_file_between_hosts` 直接机对机不绕本地。整条链丢给定时任务也行——task scope 视为已授权，凌晨无人值守一样跑。完整样例见 `docs/AI-Delegation-Cookbook.md` 的「★ 旗舰示例：开发 / 发布 / 运维 / 反馈 生命周期」。
- 查阅操作帮助：用户问「如何操作」「帮助」时，AI 会读取 web/aihelp 下的帮助文档（如本目录）后回答。
- **用户反馈与登录留言板**：登录后用户在侧边栏「反馈」菜单可向管理员提交 Markdown 反馈，AI 也能用 `submit_feedback` 代为提交、`list_my_feedback` 帮你查看进度。管理员侧通过 `list_user_feedback_admin`（支持 `status` / `unread` 过滤、`limit` / `offset` **分批查看**）、`get_user_feedback_detail`（查看单条**并自动标已读**）、`reply_user_feedback_admin`（写 Markdown 回复）、`ignore_user_feedback_admin`（忽略）、`mark_all_user_feedback_read`（一键标已读所有未读）等工具进行管理。登录页右下角的**匿名留言板**目前**没有**专用 AI 工具，管理员需直接在 `/feedback/admin/login-board` 后台审核 / 公开 / 回复 / 删除。管理员可在「系统设置 → 反馈邮件通知」开启**新反馈邮件通知**（默认关闭，开启后用全局 SMTP 推给所有绑定邮箱的管理员，带 30 秒去抖防刷屏）。详见 [feedback.md](feedback.md)。
- **可点击的选择题**：AI 在需要你确认、选择或做二次风险确认时，会直接在聊天里渲染**一排按钮**（如 ABCD 多选、是/否同意、确认/取消、危险动作红色按钮）；你可以**直接点击**答复，也可以继续在输入框里用文字补充说明。点击和文字两种方式都能被 AI 理解。OpenClaw/API 集成通道与定时/触发任务没有按钮 UI，AI 会改用纯文本列出选项让你回复。**选择卡会持久展示**：后端把 `ask_user_choice` 的动作以哨兵注释嵌入 assistant 消息落库，切换会话 / 刷新页面后仍可还原；前端还额外对"最后一条 assistant"做了 localStorage 兜底，避免"闪一下就消失"。
- **聊天中直接上传附件**：输入框 📎 支持多文件（粘贴/拖拽），含文本、图片与 **Office/PDF**；限额、落盘路径、MarkItDown 与排障见下文 **[聊天附件与富文档（Office / PDF）](#聊天附件与富文档office--pdf)**；流式排版见 **[流式分块渲染](#流式分块渲染)**。
- **AI 生成数据 / 报告 / 可视化成果物（artifacts）**：当你让 AI「导出一份表格」「生成一份 HTML 报告」「把某段日志整理成 csv 下载」时，AI 会调用 `create_chat_artifact` 把结果写入你的 `web/fs/<你>/chats/YYYY/MM/DD/<短 id>/` 目录（与聊天附件共用 `chats/` 根——附件是文件、artifact 是子目录，互不冲突）。支持两种形态：**单文件**（直接 `.csv / .md / .txt / .json / .html / .svg` 等）和 **bundle**（多文件组合如 HTML + 子目录 images/、js/、data.json，下载时服务端流式打包为 `.tgz`）。写入后 AI 在回复里以 `[标题](artifact:UUID)` 形式插入一个链接，前端自动把它增强为一张**下载卡片**（显示标题、文件数、总大小、入口文件），带「下载」按钮和「预览」按钮。
- **成果物站内模态预览**：点卡片上的"预览"按钮会在当前网页弹出模态窗（iframe 不跳转新窗口），按文件类型做对应渲染：
  - `.html / .htm` → iframe `srcdoc` 沙箱渲染（bundle 内部 `src=` / `href=` 相对资源会自动重写为带 token 的 artifact file URL）；
  - `.md / .markdown` → 使用聊天同款 Markdown 渲染器；
  - `.txt / .log / .yaml / .xml / .ini / .toml` → `<pre>` 文本原样展示；
  - `.csv / .tsv` → 自动解析为简易表格（最多 500 行，含表头粘性置顶，超出提示下载查看完整数据）；
  - `.json` → 缩进美化后 `<pre>` 显示；
  - 图片（`.png / .jpg / .gif / .webp / .svg` 等）→ `<img>` 居中预览；
  - `.pdf` → 浏览器原生 PDF 查看器 iframe。
  后端 `/api/ai/artifacts/{uuid}/file` 对文本 / 图片 / PDF / JSON 类型返回 `inline` Content-Disposition（可加 `?download=1` 强制下载）；对 bundle 预览走 HTML 源改写方案，iframe 内的子资源会自动带 token 访问。
- **会话级提示词**：可为当前会话设定专用约束（如只做部署、用简洁风格、禁止重启等），高优先级约束 AI 行为；支持 Markdown 格式与弹窗内「编辑/预览」；可由 AI 根据对话总结并替换或追加。详见下文「会话级提示词」。
- **聊天操作序列与详情**：AI 生成会话提示词或归纳最佳实践/经验时，会先获取「仅用户要求与助手指令」的操作序列（不含程序输出）；需要分析具体报错或引用终端/命令输出时，可获取含完整输出的聊天详情。详见下文「聊天操作序列与详情」。
- **低交互与运行中控制**：输入区提供会话级「低交互」开关。AI 正在流式执行时，输入区会切换为运行中控制条，可随时补充信息、暂停或停止；执行结束后自动回到普通聊天输入框。详见下文「低交互与运行中控制」。
- **内置 Markdown / 公式渲染**：聊天消息本地渲染标题、列表、表格、安全链接、代码高亮、diff/log/tree/http 块、Callout、Mermaid/Markmap/ECharts 与 LaTeX 公式；系统会压缩无意义空行。流式输出时对**已闭合**的段落/表格/代码块即时渲染，尾部未完成部分仍以纯文本或增量表格显示，减少闪动。详见下文「聊天输出格式」。

## 推荐提问方式

为了让 AI 更稳定，建议在需求中尽量说明：

- 目标主机或主机分组
- 你是要“查看”“分析”还是“直接修改”
- 是否允许重启、安装软件、改配置
- 是否只针对当前主机
- 是否需要记录为维护历史或最佳实践

推荐说法示例：

- “只检查这台主机的 Nginx 问题，不要修改配置。”
- “在当前主机上排查 502，允许查看日志与配置，但不要重启服务。”
- “对支付组批量巡检磁盘和内存，只输出异常项。”
- “为这个任务新建 AI 控制台，不要影响我当前手工终端。”

## 大文本与批量数据处理策略

- **优先脚本化**：当任务涉及大量日志、长文本、CSV/JSON、目录文件清单或批量数据时，AI 应优先使用 shell / Python / PowerShell 脚本处理，而不是把全部内容塞进上下文逐行分析。
- **先小样本验证**：复杂转换、提取、清洗、统计任务，建议先对少量样本或 dry-run 运行，确认规则正确后再处理全量。
- **修改前考虑备份**：涉及批量修改、覆盖写入、替换配置、更新数据时，默认先做可回滚备份（复制、导出、快照或同目录 `.bak`），再执行修改。
- **删除前确认风险**：涉及批量删除或不可逆删除时，AI 应先列出目标范围、数量和风险；在浏览器场景中优先用可点击确认卡让用户确认后再执行。
- **只读分析可直接做**：统计、检索、格式转换预览、生成报告等只读操作，可直接用脚本提高效率，并在结果中说明处理范围与抽样/截断情况。

## 通用数据处理能力

AI 也内置了一组轻量数据处理工具，适合在聊天中快速处理小到中等规模的数据：

- **正则处理**：`regex_process` 可做匹配、提取、统计、分割和替换预览，适合日志片段、配置片段、文本清洗规则验证。
- **字符串处理**：`string_process` 可做去空白、大小写转换、替换、切片、分割/拼接、行数/词数统计、Base64/URL 编解码、哈希计算。
- **数学与科学计算**：`math_calculate` 可安全计算常见数学表达式、数组统计、长度/质量/力/时间/温度等基本单位换算。
- **JSON/YAML 分析**：`data_query` 可解析 JSON/YAML，做结构摘要、按路径读取、递归搜索 key/value、简单列表过滤。
- **XML/HTML 分析**：`markup_query` 可解析 XML/HTML，做结构摘要、按标签或选择器查找、搜索文本、提取属性、链接和图片地址。

这些工具都是**只读处理**：它们不会直接修改文件或数据库。若需要把处理结果写回文件、批量替换或删除数据，应先按上一节的备份/确认策略执行。

## 会话级提示词

- **作用**：为当前会话设定专用约束（如「只做部署类操作」「用简洁风格回复」「禁止重启主机」等），在后续对话中**高优先级**约束 AI 行为。
- **编辑方式**：在聊天栏点击「会话提示词」打开弹窗，可直接编辑；内容**建议使用 Markdown 格式**（如 `## 小标题`、`- 列表`、`` `代码` ``），便于阅读。
- **预览**：弹窗内提供「编辑」与「预览」切换，预览时按 Markdown 渲染显示，方便查看效果。
- **由 AI 总结**：可点击「由 AI 总结（替换）」或「由 AI 总结（追加）」：系统会根据**最近对话中的用户要求与助手指令**（不含程序输出与日志）归纳出一段会话级提示词，并覆盖或追加到当前会话。总结过程中可随时关闭窗口，完成后会自动保存。
- **通过对话更新**：用户可以说「把上述要求记到会话里」「更新会话提示词」等，AI 会调用 update_session_prompt 写入或追加内容；内容只应归纳用户要求与执行意图，不包含终端输出或日志原文。

## 低交互与运行中控制

### 低交互开关

- **位置**：AI 助手、主机 AI 运维、本机管理 AI 的聊天输入区域都有会话级开关，中文显示为「低交互」，英文显示为 `Auto`。
- **默认**：关闭。关闭时，AI 在完成一段任务、遇到新问题或需要继续旧任务时，会更多地询问用户是否继续。
- **开启后**：AI 会减少“是否继续”的询问，能继续执行时优先连续推进；只有在轮次耗尽、执行失败、缺必要条件，或你明确暂停/停止时才停下反馈。
- **持久化**：开关按会话保存；切换会话时会恢复该会话自己的设置。

### 运行中补充、暂停、停止

AI 正在输出或调用工具时，普通输入框会临时替换为紧凑的运行中控制条：

- **补充并调整**：输入新条件、错误原因、约束或澄清后发送。AI 会优先整合这些信息，再决定后续步骤。
- **暂停**：让 AI 暂停推进，适合你临时提问、检查输出或补充关键背景。
- **停止**：请求终止当前 agent 循环。若此时正在等待慢工具，系统会尽量在等待间隙中断，并把工具卡标为已被运行时控制打断。
- **焦点行为**：运行中控制条出现时会自动聚焦补充输入框；AI 完成后自动回到普通聊天输入框，后续消息不会继续被当作运行中控制指令。

### 与“中断”的关系

- **停止 / 中断** 都用于终止当前正在进行的 AI 任务。
- **补充** 不会终止任务，而是把新信息插入当前会话，让 AI 调整计划。
- **暂停** 更适合“先别继续，我要问一下/补一条信息”；恢复或再次发送消息后再继续。

## 聊天输出格式

### Markdown

AI 聊天支持常见 Markdown：

- 标题：`## 标题`、`### 标题`
- 列表、引用、表格、分隔线
- 安全链接：`<a href="..." target="_blank" rel="noopener noreferrer">文本</a>`
- 代码块：建议带语言名，如 ```bash、```python、```json、```sql、```diff、```log
- Callout：`> [!NOTE] 标题`、`> [!WARNING] 标题`、`> [!TIP] 标题`

系统会自动压缩多余空行，并尽量修复安全 HTML 标签中的空格问题，避免出现 `<ahref=...>` 这类展示错误。

### 流式分块渲染

AI **流式回复**时，前端不会等整段文字结束才一次性排版，而是按「块」增量渲染，减少闪烁并尽早看到结构化内容：

- **已闭合的 fenced 代码块**（含 ```mermaid、```markmap、```echarts-option 等）：块写完后立即按对应渲染器展示。
- **完整 Markdown 表格**（含表头分隔行，且表格后有空行）：表格段落闭合后渲染为 HTML 表格；流式过程中若仅 tbody 在增长，会尽量只更新表格主体而不重绘整表。
- **双换行段落**：普通段落以 `\n\n` 为界，段落完整后走 Markdown 排版。
- **尾部未闭合内容**：仍按纯文本或局部表格增量显示，直到该块闭合。

因此长回复里，你会先看到已完成的代码块、表格或段落，末尾仍在打字的部分保持为普通文本。会话结束或切换消息时会做一次收尾渲染。

### 公式

推荐让 AI 使用标准 LaTeX 数学定界符：

- 行内公式：`$F = ma$`
- 块级公式：

```text
$$
F = G \frac{Mm}{r^2}
$$
```

前端会优先使用可用的公式渲染器；没有外部公式库时，会使用本地 fallback 渲染常见表达式，包括 `\sqrt{}`、`\frac{}{}`、`^`、`_`、`\mathbf{}`、`\mathrm{}`、`\text{}`、`\times`、`\approx` 等。少数非常复杂的 LaTeX 宏可能只做近似展示。

### 图形与图表

- 流程图 / 时序图 / 拓扑图：使用 ```mermaid
- 思维导图：使用 ```markmap
- 统计图：使用 ```echarts-option

这些能力都走本地资源；Mermaid 还会做预检查和常见语法修复。

## 聊天附件与富文档（Office / PDF）

### 适用场景

- 让 AI 阅读合同、报表、幻灯片、说明书等 **PDF / Word / Excel / PPT**
- 与文本、图片附件一样，在输入框 **📎** 上传或粘贴/拖拽（可多文件）

### 支持类型与限额

| 类别 | 常见扩展名 | 说明 |
|------|------------|------|
| 文本 | md, txt, json, csv, log, html 等 | 直接按文本读取 |
| 图片 | png, jpg, gif, webp, svg 等 | 可开「支持图像识别」内联；多轮可复用 `ai_description` |
| 富文档 | pdf, docx, pptx, xlsx 等 | kind=`document`，服务端 **MarkItDown** 转 Markdown |

- 单文件默认 **20 MB**，单会话累计约 **500 MB**
- 落盘：`web/fs/<你>/chats/YYYY/MM/DD/<uuid>.<ext>`（详见 [filesystem.md](filesystem.md) §3.6）

### AI 如何读取

1. 发送带附件的消息后，末尾会有 **📎 附件** 清单（含 uuid、kind）
2. 分析 Office/PDF 前，应让 AI 调用 **`read_chat_attachment(uuid=…)`**
3. 成功转换时返回 `content`（Markdown）且 `converted_from_markitdown: true`
4. 同目录旁路缓存 `<原文件名>.extracted.md`，删除附件时一并清理

### 部署与配置（管理员）

| 变量 | 默认 | 含义 |
|------|------|------|
| `EDGEOPS_MARKITDOWN_ENABLED` | true | 是否对 document 类附件做转换 |
| `EDGEOPS_MARKITDOWN_MAX_OUTPUT_CHARS` | 500000 | 转换结果最大字符数，超出会截断 |
| `EDGEOPS_CHAT_ATTACHMENT_MAX_BYTES` | 20MB | 单文件上限 |
| `EDGEOPS_CHAT_ATTACHMENT_SESSION_QUOTA_BYTES` | 500MB | 单会话累计上限 |

Docker 镜像需安装 `libmagic1` 与 Python 包 `markitdown`；依赖变更后须 `docker compose … up -d --build` 重建。

### 常见问题

- **AI 说没看过文档**：明确 uuid 或让 AI 先 `read_chat_attachment`。
- **转换失败或内容为空**：检查扩展名是否支持、文件是否损坏、MarkItDown 是否被关闭。
- **表格在流式过程中仍是纯文本**：属正常——表格需**写完整且表后有空行**才会整块渲染，见上文「流式分块渲染」。

## 聊天操作序列与详情

- **操作序列（get_session_operations）**：返回「仅用户消息 + 助手指令/决策」的按时间序列表，**不包含**程序输出（如终端输出、命令结果、工具返回的长日志）。适用于：
  - 生成或更新会话级提示词时，让 AI 基于「用户要做什么、助手决定做什么」归纳，而不是基于大段日志；
  - 归纳最佳实践或经验时，只参考操作意图与步骤，避免把日志当依据。
- **聊天详情（get_session_chat_detail）**：当 `include_tool_results=false` 时与操作序列一致；当 `include_tool_results=true` 时返回**完整消息内容**（含助手回复中的执行结果、报错、日志等）。适用于：
  - 用户或 AI 需要分析某次命令的具体报错、引用某段终端输出时；
  - 需要从历史对话中查找某次执行的完整输出时。
- 在对话中让 AI「根据当前对话总结会话提示词」或「归纳成最佳实践」时，AI 会先调用 get_session_operations 再归纳；若用户问「上次执行某某命令的输出是什么」，AI 可调用 get_session_chat_detail(include_tool_results=true) 获取详情。

## 控制台自动切换

- **默认**：AI 向某个 **AI 创建** 的控制台输入时，界面会自动切换到该控制台，便于用户看到 AI 操作。
- **用户终端保护**：若用户自行切换到「用户创建」的控制台，自动切换暂停；AI 不会为了执行命令而把界面抢切过去。
- **恢复时机**：再切换到「AI 创建」的控制台后恢复。
- **关闭**：勾选「不自动切换」后，AI 仍可向控制台发送内容，但界面不再自动切台。本机管理页控制台同样支持上述行为。

## AI 与用户终端的边界

当前系统遵循以下规则：

- AI **只能使用 AI 创建的 SSH 控制台**。
- AI **不能操作用户创建的 SSH 控制台**。
- 若当前聊天区域没有 AI 控制台，AI 需要先创建后才能进行交互式终端任务。
- 用户如果正在自己的控制台里操作，AI 不会强行切换过去。

这意味着：

- 你要人工接管时，适合使用用户控制台。
- 你要让 AI 连续执行多步任务时，适合让 AI 创建独立控制台。
- 你要让 AI 并行处理多个任务时，可以让 AI 创建多个 AI 控制台分别处理。

## 用户配置（系统配置与 AI 配置）

- **系统配置**（如全局 API Key、模型等）：仅管理员可查看与修改；普通用户不可编辑。
- **每用户 AI 配置**：每个用户可独立配置自己的 **模型类型**（阿里云 DashScope / Ollama / OpenAI 或自定义）、服务地址与模型、**上下文长度**（字符数上限，0=不限制，用于避免上下文溢出）、系统提示词、自动审批、**支持图像识别**（默认开启：聊天中的图片会以多模态形式送给模型；若所用模型或网关不支持视觉，可关闭此项，改为仅通过附件清单 + `read_chat_attachment` 等方式处理图片）等。
- **未配置自有 API Key 时（系统共享 Key 配额）**：若用户尚未填写自己的 API Key，系统会**自动使用管理员配置的系统 KEY** 代为调用，并计入该用户的**调用次数上限**（默认 **2000 次**，可用 `EDGEOPS_SYSTEM_AI_USAGE_LIMIT` 调整）。**用户一旦配置了自己的 KEY，则不再计入该上限，即无次数限制。** 在使用系统共享 Key 期间：
  - 每一轮对话中，AI **首条 assistant 回复**开头会插入一行横幅，提示**系统共享 Key 配额**、已用次数与剩余额度（与当前前端文案一致）；
  - 「系统设置 → 我的 AI 配置」页面顶部同步显示额度进度，便于查看剩余次数；
  - 达上限后，AI 不再调用模型，而是自动回复固定说明，引导用户在「我的 AI 配置」中填写自有 Key，或联系管理员处理配额。
- **管理员如何重置配额或改为自有 Key**：
  - **UI（推荐）**：管理员进入「用户管理」，在目标用户行点击 **「AI 配额」**，可查看该用户已用/剩余次数、是否已配置自有 KEY，常见操作包括：
    - **重置次数**：将该用户**系统 KEY** 调用计数清零，重新获得默认额度（如 2000 次）；
    - **解除限制（应用系统默认配置到用户）**：把系统默认 AI 配置（Key/URL/Model）**写入该用户**，其后该用户走自有配置项，**不再受系统 Key 次数限制**（等效于用户自行在「我的 AI 配置」中填好 Key）。
  - **AI 技能**：也可在对话中触发，例如 `reset_user_system_ai_usage`、`apply_system_ai_config_to_user`。
- 配置路径一般在「系统设置」或个人「AI 配置」中。

## 其他交互

- **导出 Markdown**：可将当前会话的聊天记录导出为 Markdown 文件，便于存档或分享。
- **清空 N 条以后**：可保留前 N 条消息、删除其后的全部，用于在长会话中「只保留最近一段」以减轻上下文负担。
- **活动主机**（主机详情页）：左侧可显示最近打开过的主机，点击快速切换；关闭某活动主机会清理该页缓存，下次从列表再打开为全新页面。
- **图形化输出**：聊天中支持网络关系图、流程图、思维导图和图表等结构化输出，并可另存为图片；若要表达拓扑、流程或依赖关系，建议直接要求 AI 用图形化方式展示。
- **管理你的成果物**：所有 AI 生成的 artifact 都会同时出现在侧边栏「文件系统」→ `chats/<日期>/<短 id>/` 目录下（与当日上传的聊天附件并列），可直接在文件面板里浏览、重命名、删除；也可通过 REST 接口 `GET /api/ai/artifacts?session_id=...` 列出当前会话的 artifact，`DELETE /api/ai/artifacts/{uuid}` 删除（同步删除磁盘目录）。AI 在对话中也能用 `list_chat_artifacts` / `read_chat_artifact_file` 回头引用自己之前的成果物做进一步加工。

## Mermaid 自动修复与持久化

- **预检查**：Mermaid 在渲染前会先做源码预检查，自动清理常见噪音与误写，减少直接报错。
- **自动修复**：当前已覆盖多类常见问题，例如：
  - `flowchart` 中把 `ID[/path text]` 这类路径/URL 风格标签自动改写为 `ID["/path text"]`
  - 清理 Mermaid 定义前的无关文本
  - 忽略 `classDiagram` 中 Mermaid 不支持的 `package { ... }` 分组
  - 统一常见 Unicode 箭头、破折号等符号
- **规则链**：前端将 Mermaid 清洗逻辑按“规则链”组织，后续新增修复规则时可继续按规则追加，便于维护。
- **写回聊天历史**：若某条助手消息中的 Mermaid 被自动修复，系统会尝试把修复后的源码回写到该条会话消息。这样下次重新打开聊天记录时，通常直接读取已修复版本，无需再次重复修复。
- **适用范围**：全局 AI 助手、主机详情 AI、本机管理 AI 三处聊天页共用这套 Mermaid 预处理与写回逻辑。

## 安全与权限

- 所有执行类操作（命令、上传、创建主机、写主机知识等）均由服务端**程序逻辑**校验权限：普通用户仅能操作自己创建/归属的资源；管理员可操作全部。
- 敏感信息（密码、主机知识、控制台输出）仅供 AI 内部使用，不会在回复中原文泄露。
- **生产环境建议**：对重要主机谨慎开启「自动同意」工具调用；在**主机级提示词**中写明禁止操作、变更窗口与审批要求，必要时保持逐条确认，避免误执行高危命令。
