# ESXi 主机接入步骤手册

毛竹 通过 **SSH** 管理 ESXi 主机。ESXi 默认通常关闭 SSH，所以要先启用 SSH，再把主机加入 毛竹。

接入成功后，你可以像管理普通 SSH 主机一样，用 毛竹 或 AI 助手对 ESXi 做日常运维操作。

---

## 1. ESXi 接入前先知道什么

要接入 ESXi，至少需要：

- 你能登录 ESXi 管理界面或控制台
- ESXi 已启用 SSH
- 22 端口可以访问
- 你有可登录的账户，一般为 `root`

### 接入后能做什么

- 执行 ESXi 命令
- 打开控制台
- 让 AI 协助巡检和排障
- 查看主机、虚拟机、存储、网络相关信息

---

## 2. 推荐接入顺序

建议按以下顺序：

1. 在 ESXi 上启用 SSH
2. 确认 22 端口可达
3. 在本地先验证 SSH 登录
4. 在 毛竹 中创建凭证和主机
5. 执行简单命令验证

这样做能减少接入后的排障成本。

---

## 3. 方式一：通过 vSphere Client 开启 SSH

这是最常见、也最推荐的方式。

### 步骤

1. 登录 vSphere Client
2. 在清单中选择目标 ESXi 主机
3. 进入 **配置 / Configure**
4. 找到 **系统 / Services**
5. 找到 **SSH**
6. 点击 **启动**
7. 如需开机自动启用，可把策略设为随主机启动

### 你通常还需要知道

- 默认 SSH 端口一般是 `22`
- 登录用户通常是 `root`

---

## 4. 方式二：通过 ESXi 主机控制台（DCUI）开启 SSH

适合无法通过 vSphere Client 操作，或你正在物理机 / 带外控制台上处理。

### 步骤

1. 连接到 ESXi 主机控制台
2. 按 `F2`
3. 输入 root 密码
4. 进入 **Troubleshooting Options**
5. 选择 **Enable SSH**
6. 启用后退出

这样 SSH 服务就会启动。

---

## 5. 方式三：通过命令开启 SSH

如果你已经通过其他方式拿到了 ESXi Shell 或 SSH，会更方便。

### 示例命令

```bash
esxcli system ssh set -e true
```

### 建议

- 执行前先确认你当前在正确的 ESXi 主机上
- 如果要长期启用，记得确认启动策略

---

## 6. 开启后如何验证

不要一启用就直接在 毛竹 中接入，建议先验证。

### 推荐检查项

- SSH 服务是否真的启动
- 22 端口是否可访问
- root 账号是否可登录

### 推荐测试步骤

1. 先从你的管理机器尝试 SSH 登录
2. 成功后再到 毛竹 中新增主机

如果本地都连不上，毛竹 通常也无法使用。

---

## 7. 在 毛竹 中添加 ESXi 主机

SSH 就绪后，就可以在 毛竹 中接入。

### 推荐步骤

1. 在凭证管理中创建 ESXi 登录凭证
2. 进入主机管理
3. 新增主机
4. 主机填写 ESXi 的 IP 或域名
5. 端口填写 `22`
6. 绑定对应凭证
7. 保存
8. 执行简单命令验证

相关文档：

- [credentials.md](credentials.md)
- [hosts.md](hosts.md)

---

## 8. 接入成功后建议做什么

接入完成后，建议先做基础验证，而不是立刻做复杂操作。

### 推荐步骤

1. 执行简单命令确认响应正常
2. 打开控制台看是否可持续交互
3. 让 AI 先做只读巡检
4. 确认没有问题后再做修改类操作

### 适合先做的只读任务

- 查看主机状态
- 查看网络配置
- 查看虚拟机列表
- 查看存储信息

---

## 9. AI 在 ESXi 上适合做什么

AI 适合：

- 做只读巡检
- 解读命令输出
- 协助排障
- 帮你生成标准化命令

建议：

- 先让 AI 查看，不要一上来就改
- 如果要改 ESXi 配置，先让 AI 说明计划
- 高风险动作前先人工确认

---

## 10. 常见问题

### 10.1 开了 SSH，但还是连不上

优先检查：

- 22 端口是否可达
- SSH 服务是否真的已启动
- 网络路径是否通
- 账号密码是否正确

### 10.2 vSphere Client 中找不到 SSH 服务

优先检查：

- 是否选中了正确的 ESXi 主机，而不是 vCenter
- 当前界面版本路径是否略有不同
- 是否可以改用 DCUI 开启

### 10.3 毛竹 接入成功，但操作效果不稳定

建议：

1. 先做只读命令验证
2. 再打开控制台
3. 再交给 AI 做更复杂任务

### 10.4 是否一定要一直开着 SSH

不一定。

如果只是临时维护，可以用完后关闭；如果需要长期纳入 毛竹 管理，则可按你的安全策略决定是否长期启用。

---

## 11. 推荐的使用习惯

- 接入前先验证 SSH
- 尽量先做只读巡检
- 高风险变更前先人工确认
- 生产 ESXi 主机的操作尽量保守
- 如需复用经验，处理完成后记得写维护历史或最佳实践
