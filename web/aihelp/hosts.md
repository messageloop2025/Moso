# 主机管理步骤手册

主机即通过 SSH 管理的远程服务器。每台主机通常需要：名称、IP 或域名、SSH 端口、以及一条可用凭证。

如果你是第一次使用，推荐顺序是：

1. 先准备好凭证
2. 再新增主机
3. 检测主机类型
4. 执行一条简单命令验证
5. 再决定是否加入分组、补充主机知识、交给 AI 持续操作

---

## 1. 新增一台主机

### 适用场景

- 接入一台新的 Linux 服务器
- 新增一台 ESXi 主机
- 新增一台已安装 OpenSSH 的 Windows 主机

### 操作步骤

1. 进入「主机管理」页面。
2. 点击「新增」。
3. 填写主机基础信息：
   - **名称**：建议写清环境和用途，例如“生产-pay-api-01”
   - **主机**：填写 IP 或域名
   - **端口**：默认一般是 `22`
   - **描述**：可选，简短说明
   - **别名**：可选，多个用逗号分隔；便于 AI / OpenClaw 用昵称搜索（`list_hosts` 会匹配别名）
   - **用途说明**：可选，说明本机职责（如生产 Web 入口）；可在 **主机详情 → 详情** 中修改
4. 选择凭证：
   - 如果凭证已经存在，直接选已有凭证
   - 如果还没有，勾选新建凭证并填写用户名、密码或密钥
5. 保存主机。
6. 保存后，建议立刻做两件事：
   - 检测主机类型
   - 执行一条简单命令确认可连

### 推荐命名方式

- `生产-nginx-01`
- `测试-mysql-02`
- `香港-wireguard-01`
- `客户A-web-01`

这样做的好处是：后续在服务器树、批量任务和 AI 对话里都更容易识别。

### 别名与用途说明（给 AI / OpenClaw 用）

- **别名**：可多个。用户说「看下那台 Web1」时，若已为该机配置别名 `Web1`，AI 调用 **list_hosts(q="Web1")** 更容易命中。
- **用途说明（remark）**：说明机器**干什么**，与「描述」可同时使用；会进入运维助手的「当前主机列表」上下文，集成会话绑定主机时也会展示。
- 在 **主机详情 → AI 运维** 里对话时，可请 AI 用工具 **update_host** 为**当前绑定主机**追加别名或修改用途说明（需具备相应权限）。

## 2. 检查一台主机是否接入成功

新增后，不建议直接做复杂操作，先做最小验证。

### 建议验证步骤

1. 先执行“检测类型”
2. 再执行一条简单命令
3. 再打开控制台确认交互正常

### 推荐验证命令

Linux / macOS / BSD：

```bash
whoami
hostname
pwd
```

Windows（已安装 OpenSSH）：

```powershell
whoami
hostname
pwd
```

### 成功的表现

- 能返回 stdout
- 没有明显认证错误
- 退出码正常
- 控制台可以打开并显示提示符

---

## 3. 检测主机类型

系统支持自动检测主机类型，建议每台主机接入后都做一次。

### 检测后能得到什么

- 操作系统类型与版本
- 可能的默认 Shell
- 常见包管理器类型
- AI 后续更适合使用哪类命令

### 操作步骤

1. 在主机列表或主机详情中找到该主机
2. 点击“检测类型”或对应入口
3. 等待检测完成
4. 检查识别结果是否合理

### 为什么建议做这一步

- AI 会根据识别结果优化命令风格
- 批量执行时更容易识别不兼容主机
- 排障时可以减少“命令不适用”的问题

---

## 4. 打开主机控制台

控制台适合做连续操作，如查看日志、执行多步命令、输入 sudo 密码、排查服务。

### 操作步骤

1. 进入主机详情页
2. 点击连接或新建控制台
3. 等待 SSH 建立连接
4. 在控制台中执行命令

### 什么时候适合用控制台

- 要执行多步命令
- 要实时看输出
- 要输入 sudo 密码
- 要持续观察日志

### 什么时候不一定要用控制台

- 只执行一条简单命令
- 只想拿一次结果
- 不需要交互过程

这类情况直接用单次 SSH 执行通常更快。

---

## 5. 把主机交给 AI 操作

主机接入成功后，可以在两种地方让 AI 处理：

- **AI 助手**：适合跨主机、跨分组任务
- **主机详情 AI**：适合聚焦当前主机

### 推荐步骤

1. 确认主机能正常连接
2. 补充这台主机的主机知识
3. 让 AI 先查看状态，不要一上来就修改
4. 确认 AI 理解正确后，再允许它执行

### 推荐提问示例

- “检查这台主机的 Nginx 状态，不要修改配置。”
- “在当前主机排查磁盘占满原因，只做分析。”
- “为这台主机新建 AI 控制台，查看最近 200 行应用日志。”

---

## 6. 编辑主机

当主机地址、端口、名称、凭证发生变化时，可直接编辑。

### 操作步骤

1. 在主机列表中点击“编辑”
2. 修改需要调整的字段
3. 保存
4. 保存后重新做一次连接验证

### 建议编辑后立刻检查

- 地址是否仍然可达
- 凭证是否仍然有效
- 控制台是否能正常打开

如果你修改的是凭证绑定，尤其要重新验证。

---

## 7. 删除主机

删除是破坏性操作，建议谨慎处理。

### 删除前建议先确认

- 是否仍有批量任务依赖这台主机
- 是否仍在分组中被使用
- 是否还有人需要在服务器树中看到它
- 是否需要先导出或整理该主机知识

### 删除后的影响

- 主机会从主机列表消失
- 与分组的关联会被清理
- 该主机下的 AI 知识会被清理
- 已存在的维护历史通常仍保留，因为它按主机字符串记录

### 权限说明

- 主机所有者与管理员可删除主机实体
- 对“收到分享”的主机，接收方点击删除会执行“解除分享”，不会删除真实主机

---

## 7.1 主机分享与解除分享

### 分享主机（所有者操作）

1. 在主机管理列表找到自己的主机。
2. 点击「分享」。
3. 输入接收方用户名并确认。
4. 可在分享清单中查看当前已分享给哪些用户，必要时可撤销。

### 接收方查看分享

- 在主机管理页点击「收到分享」可查看来源用户与主机信息。
- 收到的主机会出现在主机列表与服务器树数据中，可正常搜索和运维。

### 解除分享

- 所有者可撤销指定接收方的分享。
- 接收方删除收到分享的主机时，等效于“解除分享”。
- 撤销/解除后，系统会自动清理该接收方服务器树分组中的残留关联。

### 重要说明

- 主机分享仅共享主机访问权限，不共享双方聊天会话与聊天记录。

## 8. 与凭证的关系

主机不直接保存密码或私钥，而是引用一条凭证。

### 这样设计的好处

- 一条凭证可复用到多台主机
- 改密码时只用改一处
- 更适合统一维护

### 使用建议

- 同环境同账号可复用一条凭证
- 高权限账号与低权限账号分开建
- 用清晰名称区分用途，例如“生产-root”“测试-deploy”

### 常见问题

如果执行命令或打开控制台时报“未配置有效登录凭证”，通常说明：

- 没有关联凭证
- 关联凭证已失效
- 凭证被删除

---

## 9. 常见接入失败原因

### 9.1 认证失败

优先检查：

- 用户名是否正确
- 密码是否正确
- 私钥是否正确
- 目标主机是否允许该认证方式

### 9.2 连接超时

优先检查：

- IP / 域名是否正确
- SSH 端口是否开放
- 防火墙 / 安全组是否放通
- 路由是否可达

### 9.3 能连但命令异常

优先检查：

- 是否连到了错误主机
- 主机类型识别是否正确
- Shell 环境是否受限
- 当前账号权限是否足够

---

## 10. 推荐的主机接入后续动作

一台主机接入成功后，建议继续做这几件事：

1. 放入合适的主机分组
2. 记录主机知识
3. 为常见运维动作沉淀最佳实践
4. 需要持续处理时，在主机详情 AI 中建立专用会话

### 推荐记录到主机知识的内容

- 这台主机的用途
- 项目路径
- 日志路径
- 服务名
- 是否免密 sudo
- 配置文件位置

这样 AI 后续操作这台主机时会更稳定。

## 11. AI 按名称或 IP 快速找主机

在 **AI 运维助手**对话中，可让 AI 使用内置工具缩小范围（与界面「服务器树」搜索语义一致）：

- **list_hosts**：传入 **`q`** 或 **`search`**（关键字，不区分大小写），匹配**显示名称**、**IP/域名**、**端口**、**描述**、**host_type**；若关键字为纯数字，还会匹配**主机 id**。可与 **`group_id`** 联用，只搜某分组内主机；有搜索时可传 **`limit`**（默认 100，最大 500）控制返回条数。
- **get_host_groups_tree**：传入 **`host_q`**，在分组树的各节点下只保留匹配的主机，便于按目录结构定位。

以上搜索同时覆盖“自有主机 + 收到分享的主机”。

主机很多时，优先用 **`q` 搜索**再 **`get_host_detail(host_id)`**，比让 AI 全文扫长列表更高效。
